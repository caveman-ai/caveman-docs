`caveman learn` reads the agent session history already on your disk, ranks what is eating the token budget worst first, and prints a one-line fix behind each finding. It reads and writes nothing outside its own report, needs no account, and makes no provider call.

## Run it

```bash
caveman learn
```

In a terminal this opens a keyboard menu. `--plain` prints the same thing as text:

```bash
caveman learn --plain
```


Sources scanned by default are Claude Code, Codex, Gemini CLI and opencode. Aider is included when `CAVEMAN_AIDER_ROOT` points at its history. Narrow either axis:

```bash
caveman learn --since 7d --sources claude,codex
caveman learn --repo caveman-docs
```

## The Setup Score

The score grades your current setup, not your past spend. Four components, each a penalty:

| Component | What it measures |
|---|---|
| `config_tax` | Tokens your config loads into every turn, against your median context size |
| `dumbzone` | The share of turns that ran past half the context window |
| `dead_load` | Skill description tokens for skills that never get invoked |
| `subagent_pressure` | Spawn volume across the scanned sessions |

```bash
caveman learn report --json
```

## What a finding looks like

Each entry in `sinks` carries a class, and the class decides what may be done to it.

```json
{
  "sink_id": "config_tax:baseline",
  "practice_id": "context-compression",
  "title": "Your agent config loads ~2102 tokens into every turn",
  "class": "load_bearing",
  "basis": "observed_local",
  "tokens_per_turn": 2102,
  "evidence": {
    "claude_md_user_tokens": 1024,
    "hook_count": 2,
    "plugin_count": 2,
    "skill_count": 14,
    "skill_desc_tokens": 1078
  },
  "suggestion": "Some of this is load-bearing. The reducible parts are broken out as their own sinks below.",
  "framing": "forward_rate"
}
```

| Class | Meaning | What happens to it |
|---|---|---|
| `reducible` | A heavy file, a skill nothing invokes | A concrete diff, behind the token gate below |
| `recurring_context` | A block re-established across sessions | An offload into [cavemem](/docs/memory/offload) |
| `behavioral` | A pattern in how the agent worked | An observation with a soft suggestion, left for you to act on |
| `load_bearing` | Config the agent needs | Reported so the score stays honest, and left in place |

`config_tax` is framed as a forward rate: what your current setup will cost per turn from here. It describes the turns ahead of you.

## Preview one fix

```bash
caveman learn apply <sink_id> --dry-run
```

```text
A recurring context pattern (up to ~644 tokens) was re-established across 42 sessions
sink: recurring_context:repaste:503974f732e0bd8e
locations: [{"root_kind":"claude","rel_path":"projects/…/…jsonl","jsonl_line":1,"block_index":3,"content_sha256":"4e0dcc…"}]
gates: net-token-negative · never-dumber
nothing changed — this is a preview
```

Trimmed: the real run prints all five locators in full, each with its complete path and hash. Paths and hashes here are shortened.

A locator is a file, a line in that file, a block index within the turn and a SHA-256 of the block's bytes. The candidate carries no copy of the block itself. Whatever applies the fix re-reads the real text from the locator and checks the hash before touching anything, so a file that changed since the scan aborts rather than being edited from stale data.

## Apply fixes

```bash
caveman learn implement
```

That opens Claude Code or Codex with the current report and the `caveman-learn` guide, installing the guide first if the project does not have it. With both agents on `PATH` and a terminal, it asks which one. Name it directly to skip the question:

```bash
caveman learn implement codex --prompt "start with the heavy CLAUDE.md"
```

The agent then works one finding at a time. For each one it shows the proposed diff and the before and after token count per turn, asks yes or no, applies only on yes, and re-measures. There is no apply-all that hides the individual diffs.

## The two gates

Every applied fix passes both, and both appear in the `apply` preview.

**Net token negative.** The file that was edited is counted again after the edit. An edit that did not lower tokens per turn is reverted, not kept and explained.

**Never dumber.** An offload into memory is only complete when the block is recallable and a pointer to it sits where the block used to be. If recall returns nothing, or no pointer was written, the memory is forgotten and the source file is restored. Removing context without a working path back to it is the failure this gate exists to block.

One fix kind is deliberately outside the first gate. Writing a repeated procedure down as a skill costs prefix tokens in every session and pays back only in the sessions that hit the pattern, so re-counting a file cannot judge it. It is graded with a holdout instead:

```bash
caveman learn experiment start <label> --sink <sink_id> --fix-kind skill_distillation
caveman learn experiment arm <label> off
caveman learn experiment report <label>
```

Each arm needs at least five sessions before a verdict exists. `insufficient_data` means keep going. `regressed` means delete the skill.

## Read what fixes returned

```bash
caveman learn savings
```

Rows are grouped by how the number was obtained, strongest first: `deterministic_remeasure` re-counted the edited file, `controlled_holdout` ran the change on and off on this machine, `counterfactual_replay` re-ran real history with the change applied, and `interrupted_time_series` compares before-sessions against after-sessions with no control arm. Each group is reported on its own, because a re-counted file and a session median are different kinds of evidence.

Each row also carries an `attribution.provenance`. `intact` means the file still holds the edit. `changed_since` means someone edited past it, so part of the delta belongs to them. `target_missing` means the delta cannot be tied to the fix at all.

For a check that does not depend on history at all, run the work again: [`caveman trial`](/docs/trial) records one session through its own proxy and reports what that session weighed, so a fix you applied here shows up in a task you chose rather than in a re-count of the file you edited.

<Note tone="honest" title="These are inferred figures for one window">
Every number `learn` prints is `inferred`: a local estimate from an offline token counter over the sessions it scanned. Where the report carries spend, that is what the window cost, never what a fix would return, and it is never multiplied into a month or a year. [Numbers and limits](/docs/counting#inferred) defines the word.
</Note>

## Limits

`caveman learn` reads history. It writes nothing but its own report and its candidates under `~/.caveman/`, and the analyzer applies no edit: the consent loop in `implement` is the only writer. Behavioral findings are correlational, including the one about sessions with no commit in their window, which is an observation about where tokens went and not a verdict on the session.

To share findings without sharing content:

```bash
caveman learn export
```

That prints a digest of identities and magnitudes. Read it before you send it.
