`caveman-explore` is a read-only subagent skill that answers "where does this live" with a list of `path:line` citations. The files it reads stay in the subagent, so the main thread receives the citations and not the file contents.

Looking for a report on where your tokens already went, rather than a way to read a repository? That is [caveman learn](/docs/skill/learn).

## Install

```bash
caveman explore install
```

```text
Caveman skill installed
✓ caveman-explore: /tmp/cm-explore-demo/SKILL.md
✓ Installed plain text (--no-pixel).

1 standard SKILL.md directory installed.

Claude Code auto-loads this skill when its description matches.
```

One real run, with `--dir /tmp/cm-explore-demo`. Without that flag the file goes to `.claude/skills/caveman-explore/SKILL.md` in the current project.

```text
usage: caveman explore install [--agent claude] [--user] [--dir <path>]
  legacy alias for tools skills install caveman-explore
  --agent claude   target Claude Code (default; codex is not wired yet)
  --user           install in the Claude profile's skills directory for all repos
  --dir <path>     write SKILL.md into <path>
```

`caveman explore` is a compatibility alias. The canonical form is the same install through the skills verb:

```bash
caveman tools skills install caveman-explore
```

Claude Code is the only wired target today. Passing another agent is refused with a named reason: Codex needs verified transcript isolation first.

## Use it

There is no command to run afterwards. The skill carries a description, and Claude Code loads it when a request matches: cold-start orientation, a localization question that spans many files, or a direct search that came back empty.

```text
Find where the wrap path decides which agent profile to use.
```

The subagent fans out in its first turn with parallel `Glob`, `Grep` and `Read` calls, follows the evidence for at most one or two more turns, and replies with an evidence block and nothing else. The reply shape is fixed by `skills/caveman-explore/SKILL.md`, which carries this example:

```text
src/router/pick.go:42-71  route selection — where a model is chosen
src/router/pick_test.go:18-40  the table test covering pick()
```

One citation per line, `path/to/file.ext:START-END` followed by the reason it is relevant. No preamble, no summary, no headings. When nothing matches, the whole reply is one line:

```text
no relevant locations found
```

## Why the citations matter

A subagent's result is injected into the main thread verbatim, so the result is the cost. A prose answer that quotes the files it read spends the main context on the same bytes twice. A citation list spends it once, and the main thread reads only the ranges it decides to open.

The skill declares three tools, `Read`, `Glob` and `Grep`, and `model: haiku`. It cannot edit a file, run a command or propose a fix. Cited ranges must come from a read the subagent actually performed, so a guessed or past-end-of-file range is a contract violation rather than a rounding error.

## When to skip it

Skip it when the exact file or symbol is already named: one direct `Read` is cheaper than a delegation. Skip it when you want architecture commentary or suggested fixes, which this skill refuses to produce, and use your host's own explorer instead.

For a bounded edit or a diff review with the same compressed return, [the cavecrew presets](/docs/skill/commands#cavecrew-subagents) cover those two jobs.

## Verify and remove

```bash
cat .claude/skills/caveman-explore/SKILL.md
```

The front matter should name `caveman-explore` and list `tools: Read, Glob, Grep`. Delete that directory to remove the skill; it writes nothing else.
