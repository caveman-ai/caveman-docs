[The skill](/docs/skill) installs into 36 agents, each through that agent's own mechanism: a plugin, an extension, a skill directory or a static rule file. The [proxy](/docs/proxy) wraps a shorter list of 10, because wrapping needs a way to point the agent at a different base URL without editing its config.

## Print the matrix for your machine

```bash
npx -y github:JuliusBrussee/caveman -- --list
```

Trimmed to the ends of a 36-row table. It is the full registry, the same on every machine: `(soft)` marks the four rows the installer skips unless you name them. To find out what is on this machine, read the machine, as below.

## Where the file lands

Most rows write into the directory the Skills CLI owns for that profile. These are the ones with a fixed path or an override the installer honours:

| Agent | Path |
|---|---|
| Claude Code | `.claude/skills/<name>/SKILL.md`, or `~/.claude/skills` for every project |
| Codex CLI | `~/.codex/skills/<name>/SKILL.md` |
| Continue | `CONTINUE_GLOBAL_DIR/skills`, default `~/.continue/skills` |
| opencode | `~/.config/opencode/plugins/caveman/`, plus entries in `opencode.json` and a block in `AGENTS.md` |
| OpenClaw | The workspace skill folder plus a marker-fenced block in `~/.openclaw/workspace/SOUL.md` |
| Replit Agent | The project's `.agents/skills`, which is why its command runs without `-g` |
| Antigravity IDE | `~/.gemini/antigravity/skills` |
| Antigravity 2.0 | `~/.gemini/config/skills` |
| AiderDesk | `AIDER_DESK_HOME_DIR` or `AIDER_DESK_DIR` |
| iFlow CLI | `IFLOW_HOME` |
| Crush | `CRUSH_SKILLS_DIR`, matched exactly |

Continue needs real directories because its loader skips per-skill symlinks, so the installer copies rather than links. Use the same environment variables when you uninstall as when you installed, or the uninstaller looks in the wrong place. An existing directory or symlink that caveman does not own is reported as a conflict instead of being replaced.

## Always-on without hooks

Cursor, Windsurf, Cline and Copilot have no hook system, so the always-on path is a static rule file in the repository:

```bash
npx -y github:JuliusBrussee/caveman -- --with-init
```

That writes into every supported location it can detect: `.cursor/rules/`, `.windsurf/rules/`, `.clinerules/`, `.github/copilot-instructions.md`, `.opencode/AGENTS.md` and `AGENTS.md`. All of them come from one source file, `src/rules/caveman-activate.md`, which you can also fetch directly:

```bash
curl -fsSL https://raw.githubusercontent.com/JuliusBrussee/caveman/main/src/rules/caveman-activate.md \
  > .cursor/rules/caveman.mdc
```

Nothing global is written on this path, which makes it the one that works in a managed environment.

## The wrap list

`caveman <agent>` and `caveman wrap <agent>` launch the agent through the local proxy. Ten agents have a profile in `agents/`, each naming how the base URL reaches the agent without editing its own config file.

| Agent | Vendor | How it is wired | Tested against |
|---|---|---|---|
| Claude Code | Anthropic | `ANTHROPIC_BASE_URL` and an auth token in the environment | 2.1.259 |
| OpenAI Codex CLI | OpenAI | Environment for an API key; an ephemeral `CODEX_HOME` for a ChatGPT login | 0.153.0 |
| Gemini CLI | Google | `GOOGLE_GEMINI_BASE_URL` and `GOOGLE_VERTEX_BASE_URL` | 0.58.0 |
| Aider | OpenAI or Anthropic | `OPENAI_API_BASE` | 0.86.2 |
| Kilo Code | Kilo Code | `KILO_CONFIG_CONTENT`, your `kilo.json` untouched | 7.5.9 |
| Qwen Code | QwenLM | `QWEN_CODE_SYSTEM_SETTINGS_PATH` over an ephemeral settings overlay | 0.22.3 |
| opencode | sst | `OPENCODE_CONFIG_CONTENT`, your `opencode.json` untouched | 1.18.27 |
| Hermes Agent | Nous Research | `CUSTOM_BASE_URL` and `CUSTOM_API_KEY` | 0.19.1 |
| OpenClaw | OpenClaw | `OPENCLAW_CONFIG_PATH` over a merged config, your config read-only | 2026.8.2 |
| Pi | pi.dev | A bundled native extension, your `~/.pi` config untouched | 0.84.4 |

The versions are the agent release each profile was last exercised against, from `agents/agents.json`. [Wrap an agent](/docs/proxy/wrap) covers the runtime behaviour, and Aider is the one agent with no persistent `caveman enable` path because it has no lifecycle hook to start the proxy.

## Verify

`--list` prints the registry, so check the agent's own directory instead. For Claude Code:

```bash
claude plugin list
ls ~/.claude/skills/caveman
```

The plugin appears as `caveman@caveman`, and the plugin's hook writes the mode to `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/.caveman-active`. For any other agent, list the path from [Where the file lands](#where-the-file-lands) above. Native proxy routing is a separate question, answered by `caveman doctor <agent>`.

## Uninstall

```bash
npx -y github:JuliusBrussee/caveman -- --uninstall
```

Run it while the `caveman` CLI is still on `PATH`: it hands native agent routing to `caveman disable --all`. If the CLI is already gone it names the agents still routed and the command to run.

It removes native routing, the Claude Code hook entries and hook files, the Claude Code plugin, the Gemini CLI extension, the opencode plugin and its config entries, the OpenClaw workspace skill and marker block, and all mode state under `$CLAUDE_CONFIG_DIR`. It leaves three things behind by design: skills installed by `npx skills add`, which belong to that CLI and come off with `npx skills remove caveman`; per-repo rule files written by `--with-init`; and `$CLAUDE_CONFIG_DIR/.caveman-history.jsonl`, which holds lifetime stats.
