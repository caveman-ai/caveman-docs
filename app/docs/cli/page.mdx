`caveman` is the command surface for local tools, supported coding agents, and connected account operations. The
same binary is also available as `cave`.

## Install

```bash
npm install -g @caveman-ai/cli
caveman setup
```

The bare `caveman` npm package is unrelated. Use the scoped package name.

`setup` shows which companion binaries are available. Install or repair the signed local bundle with:

```bash
caveman setup --install
```

Artifacts are checked against a key-signed manifest and their own SHA-256 before atomic installation under
`~/.caveman/bin`. Resolution checks an explicit `CAVEMAN_*_BIN` override, `PATH`, then that directory.

## Command groups

```bash
caveman help
caveman tools
caveman cloud
```

`tools` contains local commands and needs no account. `cloud` contains connected commands and requires login.
Compatibility aliases keep older top-level commands working, but grouped discovery is the clearest way to see the
current surface.

Common local commands:

```bash
caveman tools compress < payload.json
caveman tools shrink -- npm test
caveman tools toon encode < payload.json
caveman tools mem recall "migration context"
caveman tools retrieve ccr_xxxxxxxx
caveman tools browse snapshot https://example.com
caveman tools evals run
caveman tools stats --json
caveman tools config get
```

Some commands also keep their top-level form, such as `caveman learn`, `caveman stats`, `caveman mem`, and
`caveman retrieve`.

## Launch an agent

```bash
caveman claude
caveman codex
caveman gemini
caveman aider
caveman hermes
caveman kilo
caveman openclaw
caveman opencode
caveman pi
caveman qwen
```

Native-capable shortcuts persistently enable the agent integration, then launch the host. Currently these are Claude Code, Codex, Gemini, Hermes, OpenCode, and Pi. Other profiles and explicit wrap flags use session-only wrapping. The profile registry decides binary name, protocol, setup method, hooks, and fallback. See [Wrap an agent](/docs/proxy/wrap) for what that hop actually does.

On the first interactive local wrap, the CLI can install the signed runtime bundle and continue the same command.
Non-interactive runs do not change installation state without an explicit setup command.

## Learn from local sessions

```bash
caveman learn
caveman learn --plain
caveman learn --json
caveman learn implement claude
```

The profiler is read-only. Applying a proposed file change belongs to the consent-gated `caveman-learn` skill.
See [caveman learn](/docs/skill/learn) for sink classes and edit gates.

## Stable pipelines

Compression writes payload bytes to stdout and accounting to stderr:

```bash
cat large.json | caveman tools compress > compact.json 2> report.json
```

When the engine binary is missing, this path emits original bytes and a structured zero-ratio warning. It does not
break the pipe or claim compression.

Use machine modes when output feeds another process:

```bash
caveman learn --json
caveman learn --plain
caveman stats --json
caveman tools skills list --json
```

They do not open interactive menus or prompt for input.

## Missing runtime behaviour

Most affected local commands degrade to an explicit pass-through when a companion binary is missing. Output stays
unchanged, reduction is zero, and the warning names the repair command.

`wrap` starts the [local proxy](/docs/proxy) for that session when it can. If a foreign process already owns
the port, wrap will not restart or trust it. An interactive invocation can offer to launch the agent directly
when the proxy binary is missing. A script must make sure the listener is up.

<Note tone="honest" title="The CLI is a launcher, not the engine">
The npm package does not contain compression, memory, browsing, or token-counting implementations. It resolves
and drives the public binaries. `caveman setup` is the source of truth for what this machine can run.
</Note>

## Numbers and telemetry

Local reduction figures stay `inferred`. Commands do not convert them into monthly savings or `verified` claims.

Anonymous CLI telemetry covers command name, version, platform, duration, exit class, and aggregate local token
counts. It excludes prompts, code, file paths, arguments, model names, credentials, and dollar fields. Disable it
with any of these:

```bash
caveman telemetry off
CAVEMAN_TELEMETRY=0 caveman learn
DO_NOT_TRACK=1 caveman learn
```

See [Telemetry](/docs/telemetry) for the complete payload and precedence.

## Persistent setup and inspection

```bash
caveman enable claude
caveman doctor claude
caveman inspect claude
caveman why claude
caveman disable claude
```

`enable` installs a journaled, user-scoped integration. Later plain agent launches use it too. `disable` removes the owned integration; inspect and doctor help identify drift. Use `caveman wrap claude` when you want an ephemeral session without enabling a persistent integration. Host `--help` does not trigger installation. Locked projects keep the wrap path so the lock remains enforced.

## Proxy startup after enable

In [current source](https://github.com/JuliusBrussee/caveman/blob/cc067b2b3813e3187ba656b1d908761ad3e5b904/packages/cli/src/index.ts), `enable` also tries to start the local proxy when no process listens on its configured port. Repeating `enable` retries startup even when the integration is already installed. This change is not in npm version 1.3.4.

Startup is best effort: `enable` returns without waiting for readiness. A successful integration install therefore does not prove that requests can reach the proxy. Check `caveman doctor <agent>` and the listener before starting unattended work. The command respects `wrap.proxy = false`, leaves a remote URL alone, and skips this startup for Aider. An occupied port prevents another spawn; that check alone does not authenticate the process on the port.

To use the newer CLI from a source checkout:

```bash
git clone https://github.com/JuliusBrussee/caveman.git
cd caveman
./scripts/install-local-cli.sh
```

On Windows, use `pwsh -File scripts/install-local-cli.ps1` instead of the shell script.

## Connect to your own instance

Current source adds an explicit connection to a customer-owned instance. npm version 1.3.4 does not include this command option. Ordinary hosted login remains unavailable during beta.

```bash
caveman login --instance https://caveman.example.com
# Print the browser URL without opening it:
caveman login --instance https://caveman.example.com --no-browser
caveman logout
```

Use the instance's origin, without a path, query, embedded credentials, or fragment. HTTPS is required; HTTP is accepted only for loopback development. Do not combine `--instance` with `--base-url` or `--gateway-url`.

Approve the displayed code in the browser, choose a project, and grant its access scopes. This connection creates no inference key and does not upload local request history. Anonymous CLI telemetry remains a separate setting; disable it with `caveman telemetry off`. Credentials use the CLI credential store. Logout clears stored credentials after remote revocation succeeds. If revocation fails or the instance is unreachable, credentials stay available so you can retry `caveman logout`. An externally supplied `CAVE_TOKEN` must be unset in the parent environment.

The public CLI also adds read-only project agent commands:

```bash
caveman cloud agent factory list
caveman cloud agent factory show <id>
```

These require `trace:read_metadata` access. They do not grant execution approval or policy authority. The older `cloud agent list|show|run` commands still address optimization proposals. This is a client command reference; instance operation and private implementation details are outside this guide.

## Core instructions and third-party skills

`think.core` controls the architecture-first instruction pack delivered by native hooks. It is independent of compression, recovery, and telemetry:

```bash
caveman tools config get think.core
caveman tools config set think.core off
caveman tools config set think.core on
```

Changes affect later hook events. Start a new session to clear instructions already delivered into the agent's context.

`caveman tools skills add` delegates installation to the Skills CLI and can convert newly installed supported Claude Code or Codex skill bodies into pixel pages. Use `--no-pixel` to keep plain text. Originals remain available as `SKILL.orig.md`; unprofitable conversions stay text. Imported instructions are not security-reviewed by this command. Reported reductions are per-invocation inferred estimates, not provider usage or quality proof.
