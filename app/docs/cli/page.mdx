`caveman` is the one command that runs everything local: it launches an agent through the proxy, compresses a payload, stores a memory, reads your history and reports what happened. The CLI itself is MIT JavaScript; compression and metering run in signed Go binaries it shells out to.

```bash
npm install -g @caveman-ai/cli
caveman setup --install
```

## The front screen

```bash
caveman help
```

```text
caveman

run
  caveman <agent>        run an agent on the layer  (aider | claude | codex | gemini | hermes | kilo | openclaw | opencode | +2 more — caveman run)
  caveman run -- <cmd>   run anything else on the layer

understand
  caveman learn          short setup score + top moves
  caveman status         what the layer did today

connect
  caveman login          free · 1 seat · no card

more
  caveman tools          local, no account   ·  caveman help tools
  caveman cloud          connected           ·  caveman help cloud
```

The agent list is the first eight ids from the agent registry, then a count of the rest, so it reads the same on every machine. When a required binary is missing, the screen ends with a line pointing at `caveman setup --install`.

Verbs come in two groups. `caveman tools <verb>` is local and needs no account. `caveman cloud <verb>` talks to a hosted plane and needs `caveman login` first. Every verb in both groups also works as a bare top-level verb: `caveman compress` and `caveman tools compress` resolve to the same handler.

## Local verbs

```bash
caveman help tools
```

```text
caveman tools · local, no account

think
  compress      compress stdin; use `compress catalog` for tool schemas
  shrink        run a command and keep output recoverable
  toon          convert JSON to or from compact TOON
  convert       pack installed agent skills into pixels

remember
  mem           remember, recall, or forget durable context
  retrieve      recover byte-exact compressed content

execute
  mcp           add or remove agent recovery tools
  hooks         install or remove agent hooks
  browse        browse through compressed browser tools
  skills        install agent skills, optionally as pixels
  sdk           print copy-ready SDK recipes

inspect
  stats         inspect local proxy measurements
  trial         measure one local before/after run
  evals         run local quality gates
  config        inspect or change what Caveman does
```

### think

**`compress`** reads stdin, writes the compressed payload to stdout and a JSON report to stderr. `--type <content-type>` forces a compressor, `--toon` forces the TOON re-encoder. `compress catalog` hands the input to [caveman-shrink](/docs/shrink) instead, which is the tool-schema compressor, and forwards its `lint` and `recover` arguments.

```bash
cat app.log | caveman compress
caveman compress catalog lint tools.json
```

**`shrink`** runs a command, captures stdout and stderr in arrival order, and prints the compressed result plus a recovery footer. Everything is on [caveman-shrink](/docs/shrink).

```bash
caveman shrink -- pnpm test
```

**`toon`** converts JSON to and from TOON, a compact encoding for arrays of same-shaped objects.

```text
usage: caveman toon encode|decode
```

**`convert`** renders installed agent skills to PNG pages the model reads as an image, and only where the pages beat the text.

```text
usage: caveman convert [--agent <id>] [--project] [--skill <name>] [--dir <path>]
                       [--density conservative|balanced|max] [--revert] [--dry-run] [--force]
```

`--dry-run` prints the token maths for every installed skill and writes nothing. `--revert` restores byte-identically from `SKILL.orig.md`.

### remember

**`mem`** is the front end for [cavemem](/docs/memory): `remember`, `recall`, `supersede`, `history`, `recover`, `forget` and `hook install|uninstall`.

```bash
caveman mem remember "the release tag is cut from main"
```

[cavemem](/docs/memory#through-the-cli) has the full usage screen and the output of each one.

**`retrieve`** prints the original bytes behind a recovery handle. A second argument narrows the result to the sections that match a query, by BM25, returning complete records.

```text
usage: caveman retrieve <handle> [query]
```

### execute

**`mcp`** registers or removes an MCP server in an agent's config.

```text
usage: caveman mcp install|uninstall [agent] [--server caveman|caveman-browse|caveman-cloud|caveman-delegate]
  caveman: recovery tools for streaming compression and pixel disclosure
  caveman-browse: compressed browser tools
  caveman-cloud: project-scoped reports, traces, plans, and read-only experiment evidence
  caveman-delegate: pi-harness delegate tool for bounded subtasks (opt-in via execute.delegate)
  with no agent, installs for every known agent detected on PATH.
  uninstall removes the tool registration and the marker again.
```

**`hooks`** installs the command-output hook, so a noisy shell command an agent runs gets shrunk before the model reads it.

```text
usage: caveman hooks install|uninstall [agent] [--directive <id>]
  hard rewrite: claude, codex, opencode, gemini, hermes, openclaw · manual: aider.
  with no agent, installs for every hookable agent found on PATH.
  directives: deferred-tool-loading, exploration-offload-directive
```

**`browse`** drives a local Chrome through the compressed accessibility tree. See [caveman-browse](/docs/browse).

```text
usage: caveman browse <url> [query]
       caveman browse act <uid> click|type|select|scroll [text]
       caveman browse recover <handle> [query]
       caveman browse eval <expression>
       caveman browse close
```

**`skills`** lists, previews and installs the Caveman agent skills, and wraps the official Skills CLI for anything else.

```text
usage: caveman skills list [--json]
       caveman skills preview <name>
       caveman skills install [name] [--suite <name>] [--agent claude|codex] [--user] [--dir <path>]
                              [--density conservative|balanced|max] [--no-pixel]
       caveman skills add <source> [npx-skills-add-options]
       caveman skills import <skill-dir|SKILL.md> [--out <dir>] [--dry-run] [--json]
```

**`sdk`** prints the base URLs and import lines for the client SDKs.

```text
OpenAI baseURL: $CAVE_GATEWAY_URL/openai/v1
Anthropic baseURL: $CAVE_GATEWAY_URL/anthropic
Gemini endpoint: $CAVE_GATEWAY_URL/gemini/v1beta/models/gemini-model:generateContent
TypeScript SDK: import { Cave } from "@caveman-ai/sdk";
Python SDK: from caveman_cloud import Cave

Framework snippets now live in the recipe registry:
  caveman snippets
  caveman snippets openai-ts --app my-service
```

### inspect

**`stats`** reads the local SQLite store the proxy writes and prints a summary plus an offline HTML dashboard.

```text
caveman stats — your local token and cost report

  caveman stats                    summary and visual dashboard
  caveman stats --days 7           last 7 UTC calendar days
  caveman stats --all-time         all recorded history
  caveman stats --provider openai  one provider
  caveman stats --model gpt-5.6    one recorded model
  caveman stats --auth subscription
  caveman stats --json             complete machine-readable report
  caveman stats --plain            terminal summary, no browser
  caveman stats --out savings.html --open

Filters: --provider, --model, --agent and --auth use exact recorded values.
Days: 30 by default; 1–3660, or --all-time. All dates use UTC.
The dashboard is a private, offline HTML snapshot. Run stats again to refresh.
API cost estimates and subscription API equivalents are separate. Neither
proves an invoice reduction. Unknown models and billing modes stay unpriced.
```

**`trial`** runs one session through its own proxy and reports the difference. See [caveman trial](/docs/trial).

**`evals`** replays the engine's committed fixtures behind quality graders and exits non-zero if a gate fails.

```text
usage: caveman evals run [--fixtures <dir>]
```

**`config`** reads and writes the capability document at `~/.caveman-cloud/config.json`.

```bash
caveman config get
```

```text
think.mode = compress  (default)
think.core = true  (default)
think.toon = true  (default)
think.shrink = true  (default)
think.pixel.models = []  (default)
think.pixel.density = balanced  (default)
remember.mem = true  (default)
remember.offload = auto  (default)
remember.recall = false  (default)
execute.mcp = auto  (default)
execute.browse_tool = true  (default)
execute.browse_cli = false  (default)
execute.delegate = false  (default)
execute.proxy = true  (default)
```

From a machine with nothing overridden, so every line reads `(default)`. A key set in the file or the environment prints its source instead.

`caveman config path` prints the file. `caveman config set <key> <value>` writes one key.

## Running an agent

**`caveman <agent>`** turns the native integration on for good and launches the agent. The writes are journaled and user-scoped, so `caveman disable <agent>` puts your previous values back.

```bash
caveman claude
caveman codex
```

**`wrap`**, and its alias **`run`**, launch one session and leave nothing behind.

```text
usage: caveman wrap [--off|--pixel] [--workflow <slug>] <agent> [args...]
  (default)    ephemeral stack: S4 compression + TOON best-of + recovery/output shrink where host supports a temp pack
  --off        byte-safe pass-through metering only — nothing is rewritten
  --pixel      lossy text→PNG pixel mode (model-gated); originals recoverable via caveman_retrieve
  --workflow   label this session's traffic (x-cave-workflow) so it groups by name in the dashboard
```

```bash
caveman run -- my-own-script.sh
```

**`enable`** and **`disable`** manage that persistent routing without launching anything. Both take `claude`, `codex`, `hermes`, `gemini`, `opencode`, `pi` or `aider`. `enable --detected` covers every supported agent on `PATH`; `disable --all` reverses every journaled integration.

```bash
caveman enable claude
caveman disable claude
caveman disable --all
```

**`start`** runs the proxy on its own, with no agent attached.

```text
usage: caveman start [--port 8787] [--host 127.0.0.1] [--config caveman.yaml]
```

A plain `caveman start` resolves to `record` mode, which meters without rewriting bytes. [Modes](/docs/proxy/modes) covers the other two.

**`verify`** waits for a real request to appear in the proxy's store and prints the row, which is how you prove the routing took.

```bash
caveman verify --app claude --timeout 60
```

## Setup and health

**`setup`** without a flag reports which Go binaries resolved and what each one powers.

```bash
caveman setup
```

```text
caveman setup — Go binary status
The CLI itself is plain JS; compression/metering run in these binaries.

✓ caveman-proxy   …/.caveman/bin/caveman-proxy
    powers: start · wrap · stats · verify — local compression + truthful metering
✓ caveman-engine  …/.caveman/bin/caveman-engine
    powers: compress · shrink · retrieve · toon · evals
✓ caveman-mcp     …/.caveman/bin/caveman-mcp
    powers: mcp install — agent-side recovery that lets streaming requests compress
✓ cavemem         …/bin/cavemem
    powers: remember · recall · learn offload
✓ caveman-browse  …/.caveman/bin/caveman-browse
    powers: browse + agent-side compressed browsing MCP tools — wrap auto-registers once present
✓ caveman-shrink  …/.caveman/bin/caveman-shrink
    powers: compress catalog — dedicated tool-schema compression, lint, and recovery

✓ All required binaries found. Try: caveman claude
```

One real run with the home directory replaced. When a required binary is missing, the affected commands become loud byte-safe pass-throughs and the screen tells you so.

```text
usage: caveman setup [--install] [--json] | caveman setup --agent-native <claude|codex> [--remove]
```

`--install` downloads the signed binaries into `~/.caveman/bin`. Lookup order is an environment override first, then `PATH`, then that directory. The overrides are `CAVEMAN_PROXY_BIN`, `CAVEMAN_ENGINE_BIN`, `CAVEMAN_MCP_BIN`, `CAVEMEM_BIN`, `CAVEMAN_BROWSE_BIN` and `CAVEMAN_SHRINK_BIN`, one per binary.

**`doctor`** checks the install; `caveman doctor <agent>` checks one agent's integration and `--fix` repairs a degraded one. **`update`** syncs the Go binaries to this CLI's pin and checks npm for a newer CLI. **`status`** prints what ran today. **`why`** and **`inspect`** explain one agent's current wiring.

## Connected verbs

Every verb below needs `caveman login` first. They talk to the hosted plane and do nothing locally.

```bash
caveman help cloud
```

```text
caveman cloud · connected, login required

account
  whoami        show connected identity
  projects      list or create projects
  keys          create or revoke project keys
  providers     list or verify providers
  billing       inspect billing and verified savings

evidence
  score         show scoped Cave Score
  costs         show provider-complete cost totals
  plan          show ranked inferred Cave Plan
  traces        search or export request metadata
  experiments   inspect or manage eval-gated experiments
  receipts      verify or export signed receipts

governance
  audit         import or report audit evidence
  sync          sync local metadata to connected org
  agent         inspect proposal-only optimization PRs

start: caveman login
```

Sub-forms, from the handler table: `projects list|create`, `keys create|revoke <id>`, `providers list|verify <id>`, `billing status|charges`, `receipts verify <bundle.json>|export`, and `agent list|show <id>|run <id>` plus `agent factory list|show <id>`. [What Cloud adds](/docs/cloud) explains what a connected account buys.

**`login`** has two neighbours. **`init`** logs in, reads your projects, saves the first one as the active project, and writes `.env.cave` with mode `0600` into the current directory holding `CAVE_API_URL` and `CAVE_PROJECT_ID`, then prints the SDK snippet. **`logout`** revokes the project gateway key and the remote session, then clears the stored credential; a revocation that fails leaves the credential in place and tells you to retry.

## When a verb is not found

```text
unknown command "compres" — did you mean `caveman tools compress`?
see: caveman --help
```

The suggestion is the nearest verb by edit distance across both groups and the agent ids. A token that looks like a path or resolves on `PATH` gets a different line, because the shell probably meant a program rather than an agent:

```text
not a known agent — use `caveman run -- <cmd>`
```
