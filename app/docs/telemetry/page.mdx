The `caveman` CLI sends an anonymous event when a command finishes: which command ran, how long it took, whether it succeeded, and how many tokens the local proxy processed and cut since the last event. It is on by default in an interactive terminal, off everywhere else, and three switches turn it off for good. Prompts, code, file paths and model names are never part of it.

```bash
caveman telemetry status
```

```json
{
  "enabled": false,
  "state": "off",
  "source": "runtime",
  "anonymous_id": "…"
}
```

That run was piped, so `source` reads `runtime`: a non-interactive shell turns telemetry off on its own. In a real terminal after a decision has been stored, `source` reads `config`; with an environment override in play it reads `env`. The `anonymous_id` is a random UUID minted on your machine and is shown in full when you run it.

## The three off switches

```bash
caveman telemetry off              # writes the decision to the CLI's config file
export DO_NOT_TRACK=1              # any value except empty or 0
export CAVEMAN_TELEMETRY=0         # anything except 1, true, or on means off
```

A stored decision is honoured forever, including a "no" given to an older version of the prompt. An environment override beats the stored decision, so `DO_NOT_TRACK` silences a config that says on, and `caveman telemetry on` under an active override tells you so and still sends nothing until you unset it.

Turn it back on with `caveman telemetry on`. That is the one moment a `consent_granted` event fires, carrying the anonymous id, the CLI build, the platform and a timestamp.

## When it is off without you asking

- **Continuous integration.** A truthy `CI` environment variable turns it off.
- **Not a terminal.** If either stdin or stderr is not a TTY, it is off. Piping, redirecting and running from a script all land here.
- **Help and version.** `caveman help`, `caveman version`, `--help` and `-h` skip the decision and the send.
- **Before the decision is on disk.** The first interactive run writes the decision, prints the disclosure line to stderr, and only then is anything sendable. A read-only home directory means the write fails, and the CLI stays silent from there on.

The disclosure it prints, once:

```text
anonymous usage stats on — command counts and token totals only, never prompts, code, or file paths · caveman telemetry off
```

## What one event contains

Events go to `https://api.caveman.so/telemetry/cli` as a JSON array, with a 1.5 second timeout, and a failed request is dropped rather than retried. `CAVEMAN_TELEMETRY_URL` points them somewhere else if you want to see them yourself.

| Field | What it is |
|---|---|
| `schema` | The event schema, `cli/v1`. |
| `event` | `command_run`, `runtime_bootstrap`, or `consent_granted`. |
| `anonymous_id` | The random UUID stored in your config. |
| `command` | The verb, from a fixed allowlist. A verb not on the list is reported as `unknown`. |
| `subcommand` | The second word, also from a fixed allowlist, when it matched one. |
| `agent` | The agent id for a wrap or run, when the command named one. |
| `cli_version`, `os`, `arch`, `node_major` | The build and the platform. |
| `duration_ms` | Wall time for the command. |
| `exit_class` | `ok` or `error`. |
| `error_class` | On an error: `network`, `auth`, `usage`, `unknown_command`, `exec_failed`, or `other`. |
| `ts` | An ISO timestamp. |
| `tokens_processed`, `tokens_saved`, `tokens_basis` | On `command_run` only, when the local proxy has a store to read. |

A complete event, with the fields that vary by machine replaced by `…`:

```json
{
  "schema": "cli/v1",
  "anonymous_id": "…",
  "event": "command_run",
  "command": "stats",
  "cli_version": "…",
  "os": "darwin",
  "arch": "arm64",
  "node_major": 22,
  "duration_ms": 412,
  "exit_class": "ok",
  "ts": "…",
  "tokens_processed": 18422,
  "tokens_saved": 4106,
  "tokens_basis": "inferred"
}
```

## The token fields

`tokens_processed` and `tokens_saved` are deltas, not totals. The CLI asks the local proxy for its lifetime aggregate with `caveman-proxy stats --json`, subtracts a watermark stored in the same config file, and advances the watermark. Three consequences:

- The first read on a machine seeds the watermark and reports nothing, so the event carries traffic from after the disclosure only.
- A store that went backwards, because the database was deleted or restored from a backup, re-baselines rather than reporting a negative or a second copy of history.
- A dropped request loses that delta instead of replaying it. Undercounting is preferred to double counting a savings number.

`tokens_basis` carries the basis word with the number, which is `inferred` for every local store. The receiving side cannot promote it. See [Numbers and limits](/docs/counting#inferred).

Reading the aggregate means spawning `caveman-proxy`, which runs after the command's own work with a 400 millisecond budget. A slow or wedged binary drops the token fields and the event ships without them.

## What it never contains

The table above is the whole event: an allowlisted verb (anything else ships as the literal string `unknown`), a build, a platform, a duration, an outcome and two token counts, which leaves prompts, responses, code, file paths, repository names, model names, provider names and API keys out of it entirely.

Two neighbours are separate systems. The [installer](https://github.com/JuliusBrussee/caveman/blob/main/INSTALL.md) sends Caveman telemetry nowhere, though it shells out to per-agent CLIs that reach their own registries. `caveman sync` uploads span metadata to a connected organisation's dashboard, and runs only when you are logged in and ask for it.

## Verify and undo

```bash
caveman telemetry status   # state, source, and your anonymous id
caveman telemetry off      # and it stays off
```

`status` is the one telemetry verb that leaves the decision unmade, so running it on a fresh machine shows you what would happen while leaving the machine as it was.
