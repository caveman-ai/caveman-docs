Compaction is what a budgeted run does when its conversation grows faster than its remaining budget: it evicts stale tool output, then summarises the middle of the conversation into a typed capsule, then clamps the output allowance, then stops. It is the only part of `@caveman-ai/agent` that rewrites model-visible context, and every rewrite it performs is metered from the same budget it is defending.

```ts
const result = await run(definition, input, {
  budget: {
    maxUsd: 2,
    onExhausted: "compact",
    compaction: { keepRecentTokens: 8_000, summaryMaxTokens: 2_048, maxCompactions: 1 },
  },
});
```

`onExhausted: "compact"` is the default. `"stop"` skips the rung entirely and goes straight to clamping and stopping.

## The ladder

| Rung | What it costs | What it does |
|---|---|---|
| Evict | Free | Stale tool outputs become citation pointers. Deterministic. |
| Summarise | One provider call, reserved and settled like any other | Replaces the middle with a validated capsule, keeps pinned user intent and the recent tail verbatim. |
| Clamp | Nothing extra | Lowers the next call's output allowance to what the remaining budget affords. |
| Stop | Nothing | Ends the run between calls with `stopReason: "budget_exhausted"`, the partial work and the receipt in hand. |

The budget is what triggers it. A compaction is decided between turns, after a turn that asked for tools, and only while the remaining budget still covers four cold ceilings of the next call. Waiting longer makes the arithmetic impossible: once one working call no longer fits, a summarizer of the same size plus useful work afterwards cannot fit either.

## A run that compacts

Three tool results of about 30 KB each against a 15 cent budget, with a scripted provider so the file is runnable as it stands:

```ts
import { agent, run, schema, tool } from "@caveman-ai/agent";
import { fauxModel, scriptedStream } from "@caveman-ai/agent/testing";

const readLog = tool({
  name: "read_log",
  description: "Read one service log.",
  effect: "read",
  result: "inline",
  input: schema.object({ service: schema.string() }),
  execute: async ({ service }) => ({ service, lines: "timeout on upstream call\n".repeat(1200) }),
});

const investigator = agent({
  id: "investigator",
  instructions: "Find the failure. Read the logs.",
  model: fauxModel({ priced: true }),
  tools: [readLog],
  sandbox: "host",
});

const result = await run(investigator, "Why did trace t-9 fail?", {
  budget: { maxUsd: 0.15, onExhausted: "compact" },
  assumeMeteredCredential: true,
  streamFn: scriptedStream([
    { toolCalls: [{ name: "read_log", args: { service: "api" } }], usage: { input: 8_000, output: 30 } },
    { toolCalls: [{ name: "read_log", args: { service: "worker" } }], usage: { input: 16_000, output: 30 } },
    { toolCalls: [{ name: "read_log", args: { service: "billing" } }], usage: { input: 24_000, output: 30 } },
    { text: "Upstream calls timed out.", usage: { input: 20_000, output: 20 } },
  ]),
});

console.log(result.stopReason);
console.log(JSON.stringify(result.receipt.compactions, null, 2));
```

This run reaches the evict rung and stops there: eviction alone brought the next call back inside the budget, so the summariser was never priced and the run finished normally. `modeledNetTokens` is negative here because only one working call followed the rewrite, and one call's worth of reduction did not cover the cache write the rewrite forced. ## Configuration

```ts
import { normalizeCompaction } from "@caveman-ai/agent";

normalizeCompaction();
```

```json
{
  "maxCompactions": 1,
  "keepRecentTokens": 8000,
  "summaryMaxTokens": 2048,
  "minYieldTokens": 20000,
  "headroomCalls": 3,
  "pinnedUserTokens": 20000,
  "preserveFirstUserMessage": true,
  "mode": "summarize"
}
```

Captured from `normalizeCompaction()` at source 0.2.0. `summarizerModel` and `newContext` are on the returned object too, and both are `undefined` unless you pass them, so `JSON.stringify` drops them. `summarizerModel` is a `Model`, not a function. Pass a `CompactionOptions` object to see how your own settings resolve; an invalid one throws `cave_compaction_option_invalid` rather than being rounded into something workable.

| Option | Default | What it controls |
|---|---|---|
| `maxCompactions` | `1` | Compactions that count against the cap: a summarise, or a `new-context` rollover. Free eviction does not count. Repeated compaction degrades quality in ways nothing here measures. |
| `keepRecentTokens` | `8_000` | The verbatim recent tail. |
| `summaryMaxTokens` | `2_048` | Hard cap on the summary's own output, the dominant cost of the rewrite. |
| `minYieldTokens` | `20_000` | Reduction below which the rewrite is declined as not worth its call. |
| `headroomCalls` | `3` | Working calls the post-compaction budget must still cover. |
| `pinnedUserTokens` | `20_000` | User intent carried verbatim through the rewrite, newest first. |
| `preserveFirstUserMessage` | `true` | Keeps the task that created the run, even past the pin budget. |
| `summarizerModel` | the run's own working model | A cheaper summarizer is used only when its context window covers the history. |
| `mode` | `"summarize"` | `"new-context"` installs a fresh window instead of paying for a summary. |

The default summarizer is the working model on purpose. The compaction request is built by the same request builder as a working call, with the same system prompt, the same tool definitions and the same history, so it extends the cached prefix instead of starting a second one. A summarizer with its own prompt shape diverges at the first token and forfeits that prefix, which usually costs more than the cheaper rate saves.

`mode: "new-context"` skips the provider call and seeds a fresh window from the `newContext` callback, which receives the window about to be dropped. Declaring the mode without that callback throws `cave_compaction_new_context_sink_required`, because a rollover that persists nothing is unrecoverable loss rather than compaction.

## The summary contract

`SUMMARY_SCHEMA_VERSION` is `2`. The summarizer is asked for one JSON object with an objective, typed anchors, restated constraints, decisions with their reasons, artifacts, facts, a completed/active/blocked state, next steps, digest-addressed citations and lookup hints. Anchors marked `critical` cannot be retired or paraphrased by a later generation.

- `summarizationInstruction(previous, sources)` builds the request.
- `parseContextSummary(text)` validates the answer and returns `undefined` for anything malformed, which drops the rewrite and falls through to the clamp rung.
- `validateContextSummaryTransition(summary, previous, sources)` checks a new capsule against the one it replaces and returns `{ ok, failures }`, so a required source cannot lose its anchor.
- `renderSummary(summary)` returns the snake-case wire shape carried in the follow-up request.
- `latestContextSummary(messages)` recovers the newest capsule from a conversation, and `contextSummarySources(messages, indexes)` builds the digest-addressed manifest the validation checks against.

## What the receipt records

```json
{
  "index": 0,
  "tier": "summarized",
  "preTokens": 8089,
  "postTokens": 2173,
  "pinnedSegmentIds": ["runtime.user_intent.0"],
  "elidedSegmentDigests": [],
  "summarySchemaVersion": 2,
  "cacheState": "warm",
  "meteredCost": 0.0075,
  "meteredBasis": "measured",
  "modeledNetTokens": 86567,
  "modeledBasis": "modeled",
  "workingCallsAfter": 15
}
```

`result.receipt.compactions[0]`, captured from the repository's compaction regression run against a scripted provider at source 0.2.0, reflowed onto fewer lines. `tier` is `evicted`, `summarized` or `new-context`.

The two bases are kept apart on purpose. `meteredCost` is what the summarization call actually cost in the run's denomination, and it is zero for a free eviction. `modeledNetTokens` is an estimate of the context reduction the rewrite bought over the working calls that actually followed it, net of the cache-write penalty the rewrite forced. It is never called a saving and never subtracted from any other figure on the receipt.

`cacheState` records what the provider reported on the last working call, as evidence. The affordability model still prices the summarizer cold, because the rewritten context diverges from the working call's prefix at its first changed message.

## Limits

One paid compaction per run by default, and a run that declares no budget never compacts, because nothing triggers the ladder. A summary is lossy: what survives is the pinned user intent, the recent tail, and whatever the capsule's anchors and citations name. Eviction leaves a pointer where the tool output was, so a model that needs the original bytes has to fetch them again.
