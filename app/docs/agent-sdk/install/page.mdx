Installing `@caveman-ai/agent` gives you the runtime and the `caveman-agent` command: a run needs Node 22.19 or newer and one provider credential in the environment.

```bash
npm install @caveman-ai/agent
export ANTHROPIC_API_KEY=sk-ant-…
```

npm has 0.1.0, a smaller API than these pages describe. To follow them, build from the checkout below.

## Build from the checkout

<Steps>
<div>
Clone and install.

```bash
git clone https://github.com/caveman-ai/agent-sdk.git
cd agent-sdk
npm ci
```
</div>

<div>
Build the packages. The root script runs four builds in order: the protocol, the graders, the runtime and the initializer.

```bash
npm run build
```

```text
> @caveman-ai/create-agent@0.1.0 build
> tsc
```

The last of the four. Each of the other three prints the same two lines under its own package name and version, `@pebble-agent/protocol@0.1.0`, `@caveman-ai/evals@0.1.0` and `@caveman-ai/agent@0.2.0`.
</div>

<div>
Point your project at the checkout.

```bash
npm install /path/to/agent-sdk/packages/agent
```
</div>
</Steps>

These pages were written against commit `311be40`. `npx caveman-agent --version` prints `0.2.0` when the checkout is the one you installed.

## Which credential auto() picks

`auto()` takes the first of these that is present in the environment, in this order, and prints a line on stderr naming `CAVE_MODEL` when more than one is.

| Environment variable | Model `auto()` selects |
|---|---|
| `ANTHROPIC_API_KEY` | `anthropic/claude-haiku-4-5` |
| `OPENAI_API_KEY` | `openai/gpt-5.4-mini` |
| `GEMINI_API_KEY` or `GOOGLE_API_KEY` | `google/gemini-2.5-flash` |

`CAVE_MODEL` and `.caveman/provider.json` both take precedence over the credential order, and both use the `provider/model` form. A pinned model that the configured catalog does not know fails before the first call.

## Start from a template

The initializer writes a working agent directory, an eval suite, and a build config.

```bash
npm create @caveman-ai/agent@latest my-agent -- --provider anthropic
```

```text
created my-agent (support-bot)
provider anthropic (anthropic/claude-sonnet-5)
cd my-agent
npm install
npm run ticket -- tickets/refund-request.md
review evals/support.eval.ts, then npm run build (all declared evals run within budget)
```

Captured from the initializer in the checkout with `--no-install`. The flags are `--provider anthropic|openai|google`, `--template support-bot|background-agent`, and `--no-install`. With one provider credential in the environment and no `--provider`, the initializer uses that credential. With none or with several it asks on a TTY, and in a non-interactive shell it exits with `no provider credential detected; pass --provider` or `multiple provider credentials detected; pass --provider`.

The tree it writes for `support-bot`:

```text
my-agent/
  agent.ts                         model, budget, breakers
  instructions.md                  the standing prose
  tools/lookup_order.ts            one tool() per file
  data/orders.json
  tickets/                         three sample inputs
  evals/support.eval.ts            profile, development, and holdout fixtures
  .agents/skills/refund-policy/SKILL.md
  .agents/skills/shipping-claims/SKILL.md
  .caveman/provider.json           the model the scaffolder pinned
  caveman.config.ts                defineBuild({ entry: ".", evals: "evals/*.eval.ts" })
  run.ts                           loadAgentDir() + run()
  package.json  tsconfig.json  AGENTS.md  README.md  .gitignore
```

`npm run ticket -- tickets/refund-request.md` makes a real provider call and prints the receipt at the end of the run.

<Note tone="honest" title="A scaffolded project's build fails with EISDIR">
At commit `311be40`, `npm run build` and `npm run check` in a scaffolded project both stop at `caveman-agent: EISDIR: illegal operation on a directory, read`. The source graph walker tries to read the directory URLs in the generated `run.ts` as source files. To build a lock today, write the project by hand and point `entry` at a module instead of a directory.
</Note>

A hand-written project gets past the loader: `package.json`, `agent.ts` default-exporting an `agent()`, one file under `evals/`, and a config whose `entry` names the module.

```ts
import { defineBuild } from "@caveman-ai/agent/build";

export default defineBuild({
  entry: "./agent.ts",
  evals: "evals/*.eval.ts",
  maxSearchCostUsd: 2,
});
```

```text
✗ build failed: your frozen prefix is too small for the provider to cache

  frozen prefix       ≈71 tokens (local estimate)
  provider minimum  4,096 tokens (claude-haiku-4-5)
```

`caveman-agent build caveman.config.ts` on that project, trimmed after the two figures; the command also prints why the check exists and three ways to satisfy it. The build reached the prefix check, which runs before any model-backed eval, so it spent nothing. [Evals and builds](/docs/agent-sdk/build) covers what a lock contains.

## Undo

```bash
npm uninstall @caveman-ai/agent
```

Outside your project the runtime writes durable memory under `~/.caveman/agent-memory`, or under `CAVE_AGENT_MEMORY_ROOT` when you set it, and staged sandbox copies under the system temp directory. Removing that memory directory removes every stored fact; the temp copies are per-run and go with the next reboot.

## Optional peers

Three peer dependencies are declared optional, so a default install downloads none of them. `@anthropic-ai/claude-agent-sdk` and `zod` back the `@caveman-ai/agent/claude` entrypoint. `ws` is imported at the point the session server accepts a WebSocket, and its absence leaves that one route off while the rest of the server runs. `doctor` reports which of the three resolve from your installation, by resolution rather than by importing them.
