An adapter reads a framework's own agent loop and gives you two things from it: a normalised usage record per provider call, and one hook that runs immediately before the framework's provider call, on the request the framework built. The framework keeps its loop, its retries, its tools, its streams, its aborts and its error types.

Only want the spend ceiling and exact accounting? That attaches lower down, at the provider client: [Wire transport](/docs/agent-sdk/wire).

```bash
npm install <checkout>/packages/agent <checkout>/packages/adapters/vercel-ai-sdk ai@7.0.84
```

Unreleased: this page documents `@caveman-ai/agent` 0.2.0 from source at commit 311be40 in caveman-ai/agent-sdk. Build it from the checkout as described on [Install](/docs/agent-sdk/install), then install both packages from it; `<checkout>` is the path you cloned into.

`model` and `prompt` below are your own, built the way the framework already builds them:

```ts
import { createVercelAISDKAdapter } from "@caveman-ai/adapter-vercel-ai-sdk";
import { createModelBoundary } from "@caveman-ai/agent/model-boundary";
import { ToolLoopAgent, wrapLanguageModel } from "ai";

const lifecycle = [];
const usage = [];

const adapter = createVercelAISDKAdapter({
  modelBoundary: createModelBoundary([{
    id: "deterministic-request",
    prepare: ({ request }) => ({ ...request, temperature: 0 }),
  }]),
  onLifecycleEvent: (event) => lifecycle.push(event),
  onModelUsage: (record) => usage.push(record),
});

const agent = new ToolLoopAgent({
  model: wrapLanguageModel({ model, middleware: adapter.middleware }),
  instructions: "Return one evidence-backed recommendation as JSON.",
  ...adapter.composeAgentCallbacks(),
});

const response = await agent.generate({ prompt });
```

`adapter.middleware` is a native `LanguageModelMiddleware` and `composeAgentCallbacks()` returns native callbacks, composed over any you already pass. The runnable version of this, a procurement review with its own tests, is `examples/adapters/vercel-ai-sdk` in the repository.

## What a usage record carries

`onModelUsage` fires once per completed provider call with one call's disjoint counts, in the same eleven-field record the wire transport emits: [Wire transport](/docs/agent-sdk/wire#the-accounting) prints one and explains every field, including when `cost.status` reads `estimated`, `unpriced` or `unknown`. Raw provider payloads stay out of it on purpose.

`onLifecycleEvent` receives immutable normalised events carrying stable run, step, model and tool identity, the attempt, the replay source, and the upstream native ids. A stateful validator in `@caveman-ai/adapter-kit` rejects broken ordering before an event can reach accounting.

## The hook before the provider call

`modelBoundary` middleware has `prepare`, `settled` and `failed`. `prepare` returns the request the framework will send; `settled` and `failed` observe one terminal outcome each and always hand back the native response or throw the exact native failure.

Middleware receives the request and returns the request, so the framework stays the one thing that calls the model and the one thing that retries. A middleware id has to be unique and at most 64 characters, and 64 middleware is the ceiling.

## The lanes that ship

Each adapter pins one exact upstream version, and the pin is in its manifest as well as its peer dependency, so a mismatch is visible rather than assumed.

| Adapter | Upstream pin | Shape |
|---|---|---|
| `@caveman-ai/adapter-vercel-ai-sdk` | `ai@7.0.84` | Native seam |
| `@caveman-ai/adapter-mastra` | `@mastra/core@1.63.2` | Native seam |
| `@caveman-ai/adapter-openai-agents` | `@openai/agents@0.17.0` | Native seam |
| `@caveman-ai/adapter-strands-agents` | `@strands-agents/sdk@1.15.0` | Native seam |
| `@caveman-ai/adapter-langgraph` | `@langchain/langgraph@1.4.13` | Native seam |
| `@caveman-ai/adapter-cloudflare-agents` | `agents@0.22.0` | Native seam |
| `@caveman-ai/adapter-pi` | `@earendil-works/pi-agent-core@0.83.0` | Runner |
| `@caveman-ai/adapter-claude-agent-sdk` | `@anthropic-ai/claude-agent-sdk@0.3.220` | Runner |
| `@caveman-ai/adapter-eve` | `eve@0.29.2` | Runner |

A native-seam lane attaches to a callback surface the framework already exposes. A runner lane takes a Caveman definition and executes it on that runtime instead, which is why it is the answer for Pi and the Claude Agent SDK rather than a port.

What each lane can do is in its manifest under a fixed capability vocabulary: `runLifecycle`, `modelInterception`, `contextTransformation`, `toolObservation`, `usageAccounting`, `streaming`, `abort`, `replayAwareness`, `durableObservation`, `tracing`, `compilation`.

| Lane | Declares support for |
|---|---|
| Vercel AI SDK, Mastra, Strands | lifecycle, model interception, context transformation, tool observation, usage, streaming, abort |
| OpenAI Agents | model interception, context transformation, usage, streaming, abort |
| LangGraph | lifecycle, tool observation, usage, streaming |
| Cloudflare Agents | lifecycle |

Everything absent from a row is declared `unsupported` rather than left open. Read it at runtime instead of from this page:

```ts
import { createAdapterRegistry } from "@caveman-ai/adapter-kit";
import vercel from "@caveman-ai/adapter-vercel-ai-sdk";

const adapters = createAdapterRegistry();
adapters.register(vercel);
console.log(adapters.get("vercel-ai-sdk")?.manifest.capabilities);
```

The registry validates and returns metadata. It decides discovery, and admission stays with your own code.

The three runner lanes carry an older manifest vocabulary (`run`, `stream`, `tools`, `usage`, `abort`, `durable`, `compile`). Pi is the only one that declares `compile`, and it is the only lane the compiler lowers a baseline plan for, for a tool-free agent.

## Running the conformance suite

`@caveman-ai/adapter-conformance` owns every case id, capability assignment, benchmark clock, warmup count, sample count, percentile and threshold. You supply executors for the complete required set; a missing, extra, reassigned or caller-measured entry fails before anything runs.

```bash
node packages/adapter-conformance/candidates/run-candidates.mjs --print vercel-ai-sdk
```

Trimmed above: the digests are cut to eight characters, and `environment.platform` and `testVector.executedSetSHA256` are dropped, all four present in the file. The committed report's `totals`:

```json
{
  "capabilities": { "passed": 3, "blocked": 4, "total": 7 },
  "cases": { "passed": 15, "failed": 0, "skipped": 1, "total": 16 },
  "performance": { "passed": 3, "failed": 0, "skipped": 3, "total": 6 }

```

Four of seven capabilities are blocked, each by a skip. `runLifecycle` is blocked by a skipped case, `run-lifecycle.failure` with code `fixture_unavailable`. `modelInterception`, `contextTransformation` and `streaming` are blocked by a skipped benchmark of the same code, because the candidate fixture supplies a synchronous benchmark for the other three and leaves theirs out. A skip blocks qualification rather than being rounded up, which is the intended reading for a partial native seam.

```bash
npm run test:conformance-candidates
```

That repacks the installed adapter and upstream sources, reruns the cases and the suite-owned benchmarks, validates each report's self-digest, and compares artifact digests, so a committed report stays tied to the code it describes. Benchmark callbacks must return `undefined`, which makes them synchronous; the runner warms them 250 times and measures 2,000 samples, 1,000 and 10,000 for the streaming benchmark, on a monotonic clock captured at module load, and takes the p99. The suite owns every number, sample count, clock and threshold.

## Verify and undo

The adapter is on when `onModelUsage` fires once per provider call and the counts match what the framework's own response reports. Compare the two for one generation before trusting either.

To roll back, delete the adapter object from the framework config: drop `adapter.middleware` from `wrapLanguageModel` and the spread of `composeAgentCallbacks()`. The framework keeps its native result, its native error types, and any callbacks you already passed.

## Limits

Every capability in every shipped lane is `experimental`. `certified` requires exact conformance suite and report digest fields, and no lane has them. A report is candidate evidence that results are reproducible, not a statement about runtime safety, and running the suite locally does not mint certification.

An adapter adds no model call and no proxy hop, and it makes no efficiency claim. Compaction and model routing stay off this boundary for the reason [Wire transport](/docs/agent-sdk/wire#limits) gives.

Adapter presence says nothing about compiler support. A generic lane stays baseline-equivalent unless its capability manifest proves otherwise.
