`caveman shrink` runs a command, compresses what it printed, and hands the agent a recovery handle for the original bytes. `caveman-shrink` is the sibling binary for the other noisy payload an agent reads on every call: the tool catalog.

If you want every request an agent makes to be compressed rather than one command at a time, that is [the proxy](/docs/proxy).

## Shrink a command

```bash
caveman shrink -- pnpm test
```

A 484-line test run, with one failure in the middle:

```text
PASS  tests/unit/checkout_1.spec.ts  (3 tests, 12 ms)
PASS  tests/unit/checkout_2.spec.ts  (3 tests, 12 ms)
PASS  tests/unit/checkout_3.spec.ts  (3 tests, 12 ms)
… 237 lines elided (caveman) …
FAIL  tests/unit/payment.spec.ts
  ● charge() > retries on 429
    expected 3 attempts, received 1
… 238 lines elided (caveman) …
PASS  tests/unit/orders_479.spec.ts  (2 tests, 9 ms)
PASS  tests/unit/orders_480.spec.ts  (2 tests, 9 ms)
Tests: 1 failed, 480 passed, 481 total
‹caveman: shrank · 8922→159 estimated tokens · counter o200k_base · inferred · recover: caveman retrieve ccr_e87e8a0755373d87bf81da443e58efe2›
```

One real run against a generated fixture. The failure, its assertion line, the first and last passes and the summary line survive. 8,922 tokens become 159.

The JSON report goes to stderr, so stdout stays payload:

```json
{
  "content_type": "terminal",
  "tokens_before": 8922,
  "tokens_after": 159,
  "token_count_basis": "o200k_base",
  "ratio": 0.9821788836583726,
  "basis": "inferred",
  "recovery_handle": "ccr_e87e8a0755373d87bf81da443e58efe2",
  "method": "terminal"
}
```

Trimmed: the full report also carries `token_count_before` and `token_count_after` objects and a `lossless_to_model` flag. Those objects say `"status": "measured"`, which is the tokenizer's own status for a string it counted exactly; the payload-level `basis` stays `inferred`, because the provider's count for the same string can differ. [Token counting](/docs/proxy/tokens) has both.

The command's own exit code is forwarded, so `caveman shrink -- pnpm test` fails a script exactly where `pnpm test` would.

## Get the original back

```bash
caveman retrieve ccr_e87e8a0755373d87bf81da443e58efe2
```

That prints the captured bytes, all 484 lines of them. A second argument narrows the result to the sections that match a query, returning complete records rather than plucked lines.

The store happens before the smaller view is emitted, so the handle in the footer is already valid when you read it.

## Flags

| Flag | What it does |
|---|---|
| `--` | Everything after it is the command to run |
| `--file <path>` | Shrink a file instead of running a command |
| `--stdin` | Read the payload from stdin |
| `--type <content-type>` | Force a compressor. The default for command output is `terminal` |
| `--raw` | Pass the output through untouched |

```bash
caveman shrink --file build.log
cat build.log | caveman shrink --type log
```

Output larger than 8 MiB passes through unshrunk with a warning naming the cap. `CAVE_MAX_SHRINK_BYTES` moves it.

## Automatic on a coding agent

```bash
caveman hooks install
```

That installs a hook so the agent's own shell commands route through `caveman shrink` before the model reads the output. It is conservative by design: only a known-noisy, finite, non-interactive command with no shell operators is rewritten. The allow list covers version control, package managers, build tools, test runners, type checkers, linters, search, filesystem listing and the cloud CLIs; anything outside it passes through untouched.

A pipe, a redirect or a command substitution disqualifies a command, because `shrink` executes argv directly and a shell operator would change what runs.

A hard rewrite is available on Claude Code, Codex, opencode, Gemini CLI, Hermes and OpenClaw. Aider gets a model nudge toward `caveman shrink` instead of a guaranteed rewrite.

```bash
caveman hooks uninstall
```

## Compress a tool catalog

Every tool definition an agent can call is re-sent on every request. `caveman-shrink` drops the annotation bloat and shortens long descriptions while keeping the structure the model selects on.

```bash
caveman-shrink lint tools.json
```

```text
TOOL                             BEFORE      AFTER    RATIO
create_issue                        146        110    24.7%
list_issues                         149        111    25.5%
close_issue                         146        110    24.7%
add_comment                         146        110    24.7%
list_repos                          149        111    25.5%
create_branch                       146        110    24.7%
merge_pull_request                  150        112    25.3%
search_code                         146        110    24.7%
TOTAL                              1178        884    25.0%  (basis: inferred)
```

`lint` inspects and writes nothing. To commit to it, pipe the catalog through:

```bash
cat tools.json | caveman-shrink > tools.min.json
```

```json
{"tokens_before":1763,"tokens_after":881,"ratio":0.5002836074872377,"basis":"inferred","content_type":"toolschema","recovery_handle":"ccr_a07a0c7ebcb6a4f2922bd6b916cb5a9f"}
```

Both from one real run on an eight-tool catalog. `lint` counts each tool's own definition; the piped run counts the whole document, so the two ratios answer different questions.

What the first tool looks like afterwards:

```json
{
  "description": "Use this tool to create issue. Note that you should call it only when the user explicitly asks.",
  "inputSchema": {
    "properties": {
      "owner": { "description": "The account that owns the repository. Example: acme.", "type": "string" },
      "repo": { "description": "The repository name. Example: web.", "type": "string" },
      "state": { "default": "open", "description": "Which issues to return.", "enum": ["open", "closed", "all"], "type": "string" }
    },
    "required": ["owner", "repo"],
    "type": "object"
  },
  "name": "create_issue"
}
```

Reindented for width; the key order is the compressor's own. Its input description read:

```text
Use this tool to create issue. This tool is part of the repository management
suite. Note that you should call it only when the user explicitly asks. The tool
returns a JSON object. Examples: create_issue(owner='acme', repo='web').
Title: create_issue tool.
```

The name, every parameter, the enum values, the `required` list and the `default` are byte-identical to the input. The description kept its lead sentence and the sentence that says when to call the tool, and lost the suite boilerplate, the return-shape line, the example and the title marker.

The same compressor is reachable through the CLI:

```bash
caveman compress catalog lint tools.json
```

Recover the exact original from the handle in the report:

```bash
caveman-shrink recover ccr_a07a0c7ebcb6a4f2922bd6b916cb5a9f > tools.original.json
```

## What it keeps

The structural selection surface is preserved byte for byte: names, parameters, enums, `required`, and the values a model needs to build an argument, meaning `default`, `const` and `$ref` targets. Short descriptions stay whole. A long description keeps its lead plus the sentences the compressor recognises as carrying a constraint.

<Note tone="honest" title="Shorter descriptions are visible to the model">
Description reduction is lossy and the model reads the result, so identical structure is not proof that the model picks the same tool. A structural check cannot establish that; only an eval on your own catalog can. Every figure here is `inferred`, defined on [Numbers and limits](/docs/counting#inferred).
</Note>

## Limits

Input the engine cannot make smaller comes back unchanged, `ratio` 0, no handle. That is a success, not an error. Stdin into `caveman-shrink` is capped at 32 MiB; a larger catalog fails with `cave_input_too_large` rather than being buffered without limit.

`caveman shrink` captures a command's output, so the command has to end. An interactive or streaming command is the wrong shape for it, which is why the hook refuses to rewrite one.

Both binaries are BSL 1.1 behind MIT npm launchers. [Licensing](/docs/licensing) has the boundary.
