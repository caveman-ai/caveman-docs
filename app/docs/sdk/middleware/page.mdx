Caveman middleware wraps one call in the framework you already use. Before each provider call it swaps eligible tool results for a shorter copy and registers a `caveman_retrieve` tool, so the model can read the original back whenever the short copy is not enough.

Running an agent in a terminal? Swap a base URL instead: [Wrap an agent](/docs/proxy/wrap).

## Install

The adapters live in `@caveman-ai/middleware`, the runtime client in `@caveman-ai/sdk`. This page documents `@caveman-ai/middleware` 0.1.0-alpha.2 against `@caveman-ai/sdk` 1.1.0.

```bash
npm install @caveman-ai/middleware @caveman-ai/sdk ai
```

`@caveman-ai/middleware` declares no framework dependency of its own, so install the framework each adapter wraps. `ai` is the one the diff below imports. [Supported frameworks](/docs/sdk/middleware/frameworks) lists the rest with the versions each adapter accepts.

## Start the runtime

The local proxy is the runtime. It answers `/caveman/v1/middleware/*` on 127.0.0.1:8787 and holds the originals on disk. `caveman` is the CLI that installs and starts it: it needs Node.js 22.13 or newer, and `setup --install` fetches about 205 MB of signed Go binaries into `~/.caveman/bin/`. [Add the local tools](/docs/quickstart/cli) covers that install on its own. The middleware routes ship from binary release bin-v1.1.7; if `~/.caveman/bin/.bin-manifest.json` names an older release, run `caveman setup --install` again before the `curl` below.

```bash
npm install -g @caveman-ai/cli && caveman setup --install
CAVEMAN_MODE=compress caveman start
```

From another shell:

```bash
curl -s http://127.0.0.1:8787/caveman/v1/middleware/capabilities | jq '{mode, persistent, recovery, retention_seconds}'
```

```json
{
  "mode": "compress",
  "persistent": true,
  "recovery": true,
  "retention_seconds": 86400
}
```

`mode` has to read `compress` on both sides. A runtime in `record` mode measures and changes nothing, whatever the client asks for. Plain `caveman start` runs `record`.

## The diff

```diff
+import { createMiddlewareRuntime } from "@caveman-ai/sdk/middleware";
+import { withCaveman } from "@caveman-ai/middleware/ai-sdk";
+
+const runtime = createMiddlewareRuntime({ endpoint: "http://127.0.0.1:8787", mode: "compress" });
+const scope = { namespace: "support", session_id: conversationId, branch_id: "main", cache_epoch: "0" };
+
-const result = streamText(options);
+const result = streamText(withCaveman(options, { runtime, scope }));
```

`endpoint` defaults to `http://127.0.0.1:8787` and `mode` to `compress`, so both lines above are the defaults written out. `scope` is the identity of one conversation: the four parts key the stored originals, so a handle the model was given in an earlier turn only resolves under the same four. [Deploy](/docs/sdk/middleware/deployment) covers keeping it stable.

Every other adapter takes the same `{ runtime, scope }` pair. [Supported frameworks](/docs/sdk/middleware/frameworks) lists the entrypoint for each.

## What the model sees

A four hundred line worker log, sent as a tool result to the runtime in compress mode, comes back as this. Every word of it, punctuation included, is the runtime's own, captured from `POST /caveman/v1/middleware/optimize` with the handle shortened:

```text
[caveman: shortened; exact original via caveman_retrieve handle=cmw_a3bd3a55…]
2026-09-16T10:00:00Z INFO worker=0 health check passed
2026-09-16T10:00:00Z INFO worker=1 health check passed
… 396 lines elided (caveman): range worker=2..397 …
2026-09-16T10:00:00Z INFO worker=398 health check passed
2026-09-16T10:00:00Z INFO worker=399 health check passed
… caveman: elided lines resemble shown lines and match the stated invariants — answer from this view; if you truly cannot, one broad caveman_retrieve …
```

The measurement on that reply was `tokens_before: 8399`, `tokens_after` between 177 and 187 over sixteen runs, `tokenizer: o200k_base`, `basis: inferred`. The after count moves because each run mints a fresh random recovery handle, and the handle tokenises differently each time. Your own history stays byte for byte as you built it; only the outbound copy shrinks.

`cmw_…` is a grant, not a name for the bytes. The runtime writes the original into the proxy's recovery store, where it is keyed by its own SHA-256 as `ccr_…`, and hands the model a random handle that resolves only under this scope. The grant lives 24 hours from the last optimize or retrieve call that touched it; after that a retrieve answers `expired`, while the `ccr_` row stays, because that store evicts nothing. [Recoverable compression](/docs/proxy/recoverable#two-stores) is the store's side of it.

## Report statuses

`onReport` fires once per provider call with the local decision. Five statuses:

| Status | Meaning |
|---|---|
| `disabled` | The client mode is `off`, so nothing was sent to the runtime |
| `recorded` | Record mode: the runtime measured the call and returned the originals |
| `applied` | At least one tool result was replaced with a fresh shorter copy |
| `reused` | Every replacement came back from a choice frozen on an earlier turn |
| `skipped` | Nothing was replaced. `reason` says why |

The reasons a `skipped` report carries:

| Reason | What happened |
|---|---|
| `no_candidate` | The call had no eligible tool result to send |
| `protected` | The candidate was marked protected, or it is a segment kind other than a tool result or an artifact |
| `not_smaller` | The shorter copy was not smaller, so the original was kept |
| `unknown_capability` | The runtime has no transform for the content type it detected, or the plan does not allow that transform for this segment kind |
| `cache_state_unavailable` | The stored choice for this segment could not be read back, or the segment sits in a frozen cache prefix the runtime will not disturb |
| `epoch_changed` | The context manifest moved under this scope, so an earlier turn's choices no longer describe the same conversation |
| `recovery_unavailable` | The runtime could not store an original, so it refused to shorten one |
| `unsupported_shape` | A candidate had a duplicate id or content that is not well-formed UTF-16 |
| `payload_limit` | More than 256 candidates, more than 4096 manifest items, or a body over the runtime's `request_bytes` |
| `deadline` | `deadlineMs` elapsed, 100 ms by default |
| `runtime_unavailable` | The endpoint did not answer |
| `circuit_open` | Three runtime failures in a row, so the next 30 seconds bypass without asking |
| `capacity` | Sixteen optimize calls were already in flight |
| `unsupported_version` | The installed framework is outside the adapter's accepted range |
| `unauthorized` | The runtime rejected the `token` |

`runtime.ready()` answers the setup questions before the first model call: it returns the runtime's capabilities, so `mode`, `persistent` and `recovery` tell you whether the runtime is reachable, in compress mode and able to store originals. Everything after that is a per-call report.

## Verify

This program is the one the documentation runs against a real runtime. It answers from a scripted model, so every call stays on your machine and is free. Save it as `quickstart.ts` beside a `package.json` with `ai`, `@caveman-ai/sdk` and `@caveman-ai/middleware` installed, then run it once per mode.

[Download quickstart.ts](/examples/middleware/quickstart.ts)

```ts
import assert from 'node:assert/strict';
import { createHash, randomUUID } from 'node:crypto';
import { generateText, stepCountIs, tool, jsonSchema, type ModelMessage } from 'ai';
import { MockLanguageModelV4 } from 'ai/test';
import { MiddlewareRuntime, type CallReport } from '@caveman-ai/sdk/middleware';
import { withCaveman } from '@caveman-ai/middleware/ai-sdk';

const mode = process.env.DEMO_MODE ?? 'record';
if (mode !== 'off' && mode !== 'record' && mode !== 'compress') throw new Error('Invalid DEMO_MODE');
const paid = process.env.PAID_PROVIDER === '1';
const original = Array.from({ length: 800 }, (_, i) =>
  `[INFO] worker=alpha request=${i} status=healthy latency_ms=12 café 🌍\r\n`).join('');
const reports: CallReport[] = [];
const runtime = new MiddlewareRuntime({
  endpoint: process.env.CAVEMAN_ENDPOINT ?? 'http://127.0.0.1:8787',
  token: process.env.CAVEMAN_AUTH_TOKEN,
  mode, deadlineMs: 500, retrieveDeadlineMs: 5000,
  onReport: report => { reports.push(report); console.log(JSON.stringify(report)); },
});
// Use authenticated account + conversation IDs in an application. Never share this across users.
const scope = { namespace: 'docs-demo', session_id: randomUUID(), branch_id: 'main', cache_epoch: '1' };
const messages: ModelMessage[] = [
  { role: 'user', content: 'Read the log. Recover all original pages if shortened, then summarize its status.' },
  { role: 'assistant', content: [{ type: 'tool-call', toolCallId: 'read-1', toolName: 'read_log', input: {} }] },
  { role: 'tool', content: [{ type: 'tool-result', toolCallId: 'read-1', toolName: 'read_log', output: { type: 'text', value: original } }] },
];
const before = structuredClone(messages);
let handle: string | undefined;
let recoveryCalls = 0;
const scripted = new MockLanguageModelV4({
  doGenerate: async ({ prompt }) => {
    const text = JSON.stringify(prompt);
    handle ??= text.match(/cmw_[a-f0-9]{48}/)?.[0];
    const recovered = prompt.some(m => m.role === 'tool' && m.content.some(p => p.type === 'tool-result' && p.toolName === 'caveman_retrieve'));
    const recover = handle && !recovered;
    if (recover) recoveryCalls++;
    return {
      content: recover
        ? [{ type: 'tool-call', toolCallId: 'recover-1', toolName: 'caveman_retrieve', input: JSON.stringify({ handle, limit: 262144 }) }]
        : [{ type: 'text', text: 'Deterministic fixture completed.' }],
      finishReason: { unified: recover ? 'tool-calls' : 'stop', raw: recover ? 'tool_calls' : 'stop' },
      // Synthetic fixture counts; these are not provider usage or savings.
      usage: { inputTokens: { total: 0, noCache: 0, cacheRead: 0, cacheWrite: 0 }, outputTokens: { total: 0, text: 0, reasoning: 0 } }, warnings: [],
    };
  },
});
try {
  if (mode !== 'off') { const c = await runtime.ready(); console.log('capabilities', { mode: c.mode, persistent: c.persistent, recovery: c.recovery, retention_seconds: c.retention_seconds }); }
  let model: import('@ai-sdk/provider').LanguageModelV4 = scripted;
  if (paid) {
    if (!process.env.OPENAI_API_KEY || !process.env.OPENAI_MODEL) throw new Error('Set OPENAI_API_KEY and OPENAI_MODEL for paid run');
    const { openai } = await import('@ai-sdk/openai');
    model = openai(process.env.OPENAI_MODEL);
  }
  const started = performance.now();
  const result = await generateText({
    ...withCaveman({ model, tools: { read_log: tool({ description: 'Read demo worker log.', inputSchema: jsonSchema({ type: 'object', properties: {}, additionalProperties: false }), execute: async () => original }) } }, { runtime, scope }),
    messages, stopWhen: stepCountIs(4), maxRetries: 0,
  });
  assert.deepEqual(messages, before, 'Application history must keep original bytes');
  if (!paid && mode === 'off') assert(reports.some(r => r.status === 'disabled'));
  if (!paid && mode === 'record') assert(reports.some(r => r.status === 'recorded'));
  if (!paid && mode === 'compress') {
    assert(reports.some(r => r.status === 'applied' || r.status === 'reused'), 'Expected compression; inspect reports');
    assert.equal(recoveryCalls, 1, 'Native loop must execute recovery');
    assert(handle);
    let offset: number | null = 0, restored = '';
    do {
      const page = await runtime.retrieve(scope, { handle, offset, limit: 4096 });
      assert.equal(page.kind, 'original_page');
      restored += page.text;
      offset = page.next_offset;
    } while (offset !== null);
    assert.equal(restored, original, 'All exact pages must reconstruct original');
    console.log('exact recovery SHA-256', createHash('sha256').update(restored).digest('hex'));
  }
  console.log({ text: result.text, elapsedMs: Math.round(performance.now() - started), usage: paid ? result.totalUsage : 'synthetic; not provider usage', unchangedHistory: true });
} finally { runtime.close(); }
```

The ids vary per run and are shortened here. The two reports are the two model calls of one tool loop: the first replaced the log, the second reused the same frozen choice so the provider's cached prefix stays byte identical. `unchangedHistory: true` is the assertion that the application's own messages were never rewritten.

`DEMO_MODE=record` prints one `recorded` report, `DEMO_MODE=off` prints one `disabled` report, and both leave the outbound bytes alone.

## Undo

Pass the original options. `withCaveman(options, …)` returns a new object and mutates nothing, so deleting the call restores the previous behaviour exactly. `mode: "off"` on the runtime does the same from the runtime options alone, and `runtime.close()` releases the connection.
