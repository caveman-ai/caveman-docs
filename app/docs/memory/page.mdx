`cavemem` stores a fact once and hands back only the part a later question needs. Memories live in a local SQLite file, recall ranks them lexically behind a conservative threshold, and every hit reports the tokens it added to your context.

Moving a heavy `CLAUDE.md` section out of every prompt is the common case, and it has its own page: [Offload a large instruction file](/docs/memory/offload).

## Install

```bash
npm install -g @caveman-ai/cli
caveman setup --install
```

That downloads the signed binaries into `~/.caveman/bin`, `cavemem` among them. Confirm it:

```bash
caveman setup
```

```text
✓ cavemem         …/bin/cavemem
    powers: remember · recall · learn offload
```

One line of a real run, with the path shortened.

## Remember and recall

```bash
cavemem remember "the zarblat rotation key lives in vault under ops/zarblat-rotate and rotates every 90 days"
```

```json
{
  "basis": "inferred",
  "created_at": "2026-09-16T23:33:23.947191Z",
  "id": "mem_2c784d186f9a8ba7"
}
```

```bash
cavemem recall "where does the zarblat rotation key live"
```

```json
{
  "basis": "inferred",
  "hits": [
    {
      "id": "mem_2c784d186f9a8ba7",
      "text": "the zarblat rotation key lives in vault under ops/zarblat-rotate and rotates every 90 days",
      "score": …,
      "tokens_added": 23,
      "basis": "inferred"
    }
  ]
}
```

Both captured from one real run against a throwaway memory, which was deleted afterwards. `score` is replaced with `…` because BM25 is corpus-relative: the same query scores differently against a different store. `tokens_added` is what putting that hit into your prompt costs, counted offline.

Ask something the store has no match for and `hits` comes back empty, rather than carrying the nearest thing it has:

```bash
cavemem recall "how do I bake sourdough"
```

```json
{
  "basis": "inferred",
  "hits": []
}
```

## Correct a fact without losing the old one

```bash
cavemem supersede mem_2c784d186f9a8ba7 "the zarblat rotation key moved to vault ops/zarblat-rotate-v2"
```

```json
{
  "basis": "inferred",
  "created_at": "2026-09-16T23:33:28.061925Z",
  "id": "mem_2dbe6211c481da3a",
  "supersedes": "mem_2c784d186f9a8ba7"
}
```

The correction is a new memory that points back at the old one. Either id reads the whole chain:

```bash
cavemem history mem_2c784d186f9a8ba7
```

```json
{
  "basis": "inferred",
  "history": [
    {
      "id": "mem_2c784d186f9a8ba7",
      "text": "the zarblat rotation key lives in vault under ops/zarblat-rotate and rotates every 90 days",
      "created_at": "2026-09-16T23:33:23.947191Z",
      "valid_from": "2026-09-16T23:33:23.947191Z",
      "valid_until": "2026-09-16T23:33:28.061925Z",
      "superseded_by": "mem_2dbe6211c481da3a"
    },
    {
      "id": "mem_2dbe6211c481da3a",
      "text": "the zarblat rotation key moved to vault ops/zarblat-rotate-v2",
      "created_at": "2026-09-16T23:33:28.061925Z",
      "valid_from": "2026-09-16T23:33:28.061925Z",
      "supersedes": "mem_2c784d186f9a8ba7"
    }
  ]
}
```

`history` runs oldest to current and stays local. Recall returns only the current fact, so a superseded one stops reaching the model while the old wording stays auditable on disk.

## The five guarantees

**Raw text is written first.** The exact bytes land in the store before anything else happens to them, so a memory is never lost to a failure further down.

**A query below the threshold recalls nothing.** Recall ranks with BM25 and drops anything under a conservative cut, so the answer is an empty `hits` array rather than the closest available guess. It is a threshold, so a weak lexical overlap with a long memory can still clear it; read the `score` on a hit before you trust it.

**Recall is capped at 2,000 inferred tokens by default.** A recall that would exceed the budget packs up to it rather than dumping everything. Pass `token_budget: 0` explicitly for an unlimited recall; leaving it out never removes the cap.

**Recall returns the current fact only.** A superseded fact stops reaching the model, and the whole chain stays on disk where `cavemem history` can read it.

**Every compressed hit carries a recovery handle.** A hit that the engine compressed on the way out keeps a handle to the original bytes, and `cavemem recover <handle>` returns them.

## Through the CLI

The same operations, without a second binary on `PATH`:

```text
caveman mem — durable agent memory (cavemem)
  caveman mem remember <text>              store a memory
  caveman mem recall <query> [--limit N]   recall memories (lexical, conservative threshold)
  caveman mem supersede <id> <text>        replace a current fact; preserve history
  caveman mem history <id>                 show oldest-to-newest versions
  caveman mem recover <handle>             byte-exact original behind a recall hit
  caveman mem forget <id>                  delete a memory
  caveman mem hook install [agent]         opt in to auto-recall on each prompt (off by default)
  caveman mem hook uninstall [agent]       remove the auto-recall hook
```

Use `--` before text that opens with something flag-shaped, such as a Markdown rule:

```bash
caveman mem remember -- "--- the block starts with a rule"
```

## As an MCP server

Run with no arguments, `cavemem` serves its operations over stdio:

```json
{ "mcpServers": { "cavemem": { "command": "cavemem" } } }
```

## From code

Both clients shell text to the binary over stdin, which is what keeps a long memory clear of the operating system's argument-size limit. Set `CAVEMEM_BIN` when the binary is not on `PATH`. A `remember` that exceeds the binary's byte cap exits with code 65, and both clients export `MEMORY_TOO_LARGE_EXIT_CODE` so a caller can branch on it without parsing stderr.

<Note tone="warning" title="A package called cavemem on npm is a different project">
`cavemem` on npm is the same author's separate project, [github.com/JuliusBrussee/cavemem](https://github.com/JuliusBrussee/cavemem), published at 0.2.1. The TypeScript client on this page is the file in the caveman repository. Copy the file rather than installing a package by that name.
</Note>

### TypeScript

The client is one file, `mem/js/index.mjs` in the [caveman repository](https://github.com/JuliusBrussee/caveman). Copy it into your project and import it by path.

```js
import { remember, recall } from "./lib/cavemem/index.mjs";

const { id } = await remember("the deploy key lives in vault under ops/deploy");
const { hits } = await recall("where is the deploy key", 5, 2000);
```

It is Apache-2.0 and exports `remember`, `recall`, `supersede`, `history`, `forget` and `MEMORY_TOO_LARGE_EXIT_CODE`.

### Python

The client is one file, `mem/py/cavemem.py` in the same repository. Put it on your import path.

```python
import cavemem

stored = cavemem.remember("the deploy key lives in vault under ops/deploy")
hits = cavemem.recall("where is the deploy key", limit=5, token_budget=2000)
```

It is Apache-2.0, uses the standard library only, and mirrors the TypeScript surface.

## Limits

Recall is lexical, so it finds a memory by the words in it. A question phrased entirely in synonyms can miss it. Read the `score` on any hit you are about to act on.

Every number `cavemem` prints is `inferred`, a local estimate from an offline counter. [Numbers and limits](/docs/counting#inferred) defines the word. The Go core and both clients are Apache-2.0; [Licensing](/docs/licensing) has the details.
