The proxy is one local process that sits between a client and a model API: point an agent or an SDK at
`http://127.0.0.1:8787` and each request is forwarded to the provider with the credential it arrived with.
In compress mode the engine shrinks eligible context on the way out and keeps every removed byte in a local
store under a handle the agent can ask for.

Running Claude Code, Codex or another coding agent in a terminal? [Wrap an agent](/docs/proxy/wrap) does the
swap for you and starts the proxy itself.

## Start it

```bash
caveman start
```

```text
{"time":"…","level":"INFO","msg":"cache-breakpoint planner enabled","mode":"frontier"}
{"time":"…","level":"INFO","msg":"caveman proxy listening","addr":"127.0.0.1:8787","mode":"record","basis":"inferred","inbound_auth":"none"}
```

It stays in the foreground until you stop it. [Add the local tools](/docs/quickstart/cli) installs the
binaries it runs. Timestamps here are replaced with `…`.

In compress mode an advisory line comes first. With no caveman MCP server installed for any agent, it reads as below; [which doors install it for you](/docs/proxy/wrap#recovery-has-to-be-installed) is on the wrap page.

```text
→ subscription and OAuth logins stay byte-identical pass-through here: local compression needs the caveman MCP retrieve tool to recover elided detail — run `caveman mcp install <agent>` to turn it on
```

From another shell:

```bash
curl -s http://127.0.0.1:8787/health/live
```

```json
{"adapters":5,"billing":"byok","ok":true,"schema":"caveman.proxy.health.v1","service":"caveman-proxy"}
```

`adapters` counts the mounted provider routes: Anthropic, OpenAI, Gemini and Bedrock, plus the built-in
`opencode-go` compatible mount. The count rises when you configure Azure, Vertex or another `compat` mount.
Captured from caveman-proxy bin-v1.1.7.

## The base URL swap

```python
# The SDK appends /v1/messages itself, so the base URL is just the gateway + /w/my-service.
import os
import anthropic

client = anthropic.Anthropic(
    base_url="http://127.0.0.1:8787/w/my-service",
    api_key=os.environ["ANTHROPIC_API_KEY"],
)

msg = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Why is the sky blue?"}],
)
```

Printed by `caveman snippets anthropic-py --app my-service`, with the base URL resolved to the local proxy.
[Providers and base URLs](/docs/proxy/providers) has the same swap for the other SDKs.

`/w/my-service` is the attribution slug. The proxy strips it, records it on every row for this client, and
forwards the rest of the path, so one proxy can serve several apps and still tell them apart. A slug starts
with `[a-z0-9]`, continues with `[a-z0-9._-]` and is at most 64 characters. Leave it out and the path still
routes; the rows read `unlabeled-agent`.

## Three ways in

`caveman claude` is the door for a coding agent. It installs the integration for that host, starts the proxy
if nothing is listening, then launches the agent with its provider base URL pointed at the proxy.

`caveman start` is the door for your own code. It runs the proxy in the foreground and changes nothing else,
so the base URL swap above is yours to make.

The same `caveman start` proxy is also the runtime behind the framework middleware. It answers
`/caveman/v1/middleware/*` for an application that wraps one framework call instead of swapping a base URL,
which keeps the provider call in your process and sends only the tool results out for compression. See
[Middleware](/docs/sdk/middleware).

```bash
caveman start --help
```

```text
usage: caveman start [--port 8787] [--host 127.0.0.1] [--config caveman.yaml]
```

## What happens to a request

1. The `/w/<slug>` prefix is stripped and kept as the label for this request.
2. Inbound authentication runs first. With `CAVEMAN_AUTH_TOKEN` set, the request must carry that token in
   `x-cave-api-key` or `Authorization: Bearer`, and the proxy deletes the header before anything else reads
   it. Unset, which is the loopback default, every request is accepted.
3. The path is matched against the mounted provider routes. An unmatched path answers
   `404 cave_route_not_found`.
4. The credential is resolved: the one on the request wins, otherwise the provider's environment variable.
5. The body is read, capped by `CAVE_MAX_REQUEST_BYTES` (33554432 bytes by default). Over the cap answers 413.
6. The provider adapter inspects the body for model, endpoint and whether the response streams.
7. The mode decides the bytes. record forwards them untouched, compress runs the engine on eligible blocks
   and stores the originals, pixel renders allowlisted text to an image. See [Modes](/docs/proxy/modes).
8. Upstream headers are built from scratch: a fixed allowlist of the caller's headers plus the credential in
   the header that provider expects.
9. The request goes upstream. If the provider answers 4xx and the bytes were changed, the proxy retries once
   with the original bytes and books no saving for that request.
10. One row lands in `~/.caveman/caveman.db`, labelled `inferred`.

In a pinned Claude Code benchmark, wrapping used 33.2 percent fewer provider-reported input tokens across 18
paired runs, 95 percent interval 14.6 to 48.5. One case regressed 9.9 percent. All exact-answer checks passed.
That is pinned benchmark evidence, not a measurement of your traffic.

Those ten steps run before the provider call does, so every request pays the proxy's own time on top of the
provider's. [Numbers and limits](/docs/counting#latency) has what that costs.

## What it recorded

After a request has gone through, `caveman stats` reads the local store:

```bash
caveman stats
```

```json
{
  "requests": 1,
  "total_cost_usd": 0,
  "savings_usd": 0,
  "token_accounting": {
    "unavailable": 1
  },
  "auth_mode_accounting": {
    "payg": 1
  },
  "compression_tokens_before": 0,
  "compression_tokens_after": 0,
  "compression_tokens_saved": 0,
  "compression_token_count_basis": "unavailable",
  "cache_bust_requests": 0,
  "requests_eligible_for_compression": 0,
  "would_save_tokens": 0,
  "would_save_usd": null,
  "basis": "inferred"
}
```

That run was one request in record mode against a fresh store, which is why every compression figure is zero.
When the installed proxy answers without the `caveman.stats.v1` schema, `caveman stats` prints that older
output and adds `Detailed stats require an updated proxy: caveman setup --install`.
