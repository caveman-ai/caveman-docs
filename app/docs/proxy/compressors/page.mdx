A compressor is a pure byte transform for one kind of content: it takes the bytes, returns smaller bytes,
and says whether it succeeded. The engine picks one by reading the payload, and every compressor on this
page obeys the same rules about what it may remove and what it must leave behind.

## What the engine thinks your payload is

```bash
for f in orders.json app.log a.diff grep.txt build.term rows.csv values.yaml main.go page.html notes.txt
do printf "%-12s %s\n" "$f" "$(caveman-engine detect < $f)"; done
```

```text
orders.json  json
app.log      log
a.diff       diff
grep.txt     search-result
build.term   terminal
rows.csv     tabular
values.yaml  config
main.go      code
page.html    html
notes.txt    text
```

Captured from a caveman-engine build dated 2026-08-24; `caveman setup --install` today pins bin-v1.1.7, so
digits may move. `detect` needs no store and writes nothing.

## How detection decides

Detection reads bytes only. No model call, no configuration, no filename. It runs the checks in a fixed
order and takes the first that holds, so an earlier check can claim a payload a later one would also have
matched. Anything it is not confident about becomes `text`, which routes to the most conservative
compressor rather than to none.

A `<file name="…">` wrapper and a read tool's line-number gutter are stripped before the first check, so a
file listing is classified as the file rather than as prose.

| Order | Type | The signal |
|---|---|---|
| 1 | `json` | First non-space byte is `{` or `[` **and** `json.Valid` accepts the whole payload. |
| 2 | `terminal` | A raw ANSI escape sequence anywhere, or three or more bare carriage returns. CRLF line endings are excluded so ordinary Windows text never trips it. |
| 3 | `diff` | A structural marker, `\n@@ `, `diff --git `, or both `\n--- ` and `\n+++ `, plus at least four hunk or changed lines. |
| 4 | `html` | A `<!doctype html` or `<html` prefix is conclusive. Otherwise a container tag such as `<body`, `<main` or `<div`, at least six `<`, and no source-code syntax. |
| 5 | `tabular` | Parses as a CSV or Markdown table with at least eight rows. |
| 6 | `code` | At least three distinct language keywords plus a structural signal (`=>`, `::`, `->`, a brace, a Python `def` suite, or an indented block). A `#!` first line is conclusive. The code test runs the log test first and declines when it holds, so a log whose messages mention `class` falls through to row 7. |
| 7 | `log` | Four or more lines, at least three carrying a level token or a timestamp, and those lines are at least half the payload. |
| 8 | `search-result` | Six or more lines, at least four shaped `path:line[:col]:` or a bare URL, and those lines are at least a third of the payload. |
| 9 | `config` | Parses as YAML, TOML or INI with at least twelve lines. |
| 10 | `text` | Everything else. |

The ANSI check sits second on purpose. Only raw command output embeds an escape sequence, so putting the
conclusive signal early costs the later checks nothing.

Detection and compression have separate floors: a payload can be recognised and still pass through because it
is shorter than the compressor's minimum. Search results detect at 6 lines and the search-result compressor
declines under 18. Config detects at 12 lines and the config compressor declines under 14. Each compressor page
states both of its own numbers.

One row in full:

```json
{
  "transform_id": "caveman.engine.json.v1",
  "implementation_version": "1",
  "safety_classes": ["S4"],
  "deterministic": true,
  "recovery": "exact_ccr",
  "eligible_segment_kinds": ["artifact", "history", "skill", "tool_result"],
  "requires_eval": true,
  "not_smaller_fallback": "original",
  "provenance": { "kind": "native", "source_manifest_sha256": null },
  "conformance_digest": "0c3dbce89c118be01ee9d7e9a20f86f4894b4ec259bb6259723aaf0c9ea95663"
}
```

The whole document adds `schema_version` and a `registry_sha256` over the ordered capability list, so a
caller can pin the exact transform set a build offers. Every row reads `exact_ccr` and `original`: recovery
is a stored original, and a result that is not smaller falls back to the input. `S4` is the lossy class,
the one that may only run when the original was stored first.

## What every compressor guarantees

These hold for all of them, and a compressor that broke one would be a bug rather than a configuration.

**A parse problem returns the original.** Malformed input, an unsupported shape, an already-compressed
payload: the compressor returns `ok=false` and the caller forwards the bytes it was given.

**A result that is not smaller returns the original.** The engine compares token counts, not byte lengths,
and discards output that failed to shrink. See [Token counting](/docs/proxy/tokens).

**The same bytes produce the same output.** Compression is deterministic and idempotent, which is what lets
the proxy re-emit a compressed message byte-identically on every later turn instead of busting the
provider's cached prefix. That holds for every content type except JSON objects with more than one
collapsible array, where key iteration order can move the contract line between markers. The registry still
marks the JSON transform deterministic.

**Every distinct kind of content survives at least once.** Before a run of units is dropped, each one is
checked against what is still visible; a unit nothing resembles is kept, and only its later look-alikes
elide against it. This is the line between eliding repetition and truncating a document. A payload where
everything is distinct ends up not smaller, so the original goes through and nothing is claimed.

A unit's digit runs are masked to `#` only when it carries at least one token with a letter in it, so a row
of measurements is compared with its numbers intact and cannot pass for a repeated line.

**Signal lines are kept.** Each eliding compressor carries a pattern it never drops, matched case
insensitively at word boundaries. The first and last units of a payload are kept as well.

| Compressor | The pattern it never drops |
|---|---|
| [Logs](/docs/proxy/compressors/logs) | `ERROR\|FATAL\|PANIC\|EXCEPTION\|TRACEBACK\|FAIL\|FAILED\|FAILURE\|WARN\|WARNING` |
| [Terminal output](/docs/proxy/compressors/terminal) | `ERROR\|ERR\|FATAL\|PANIC\|EXCEPTION\|TRACEBACK\|FAIL\|FAILED\|FAILURE\|WARN\|WARNING` |
| [Search results](/docs/proxy/compressors/search-results) | `ERROR\|FAIL\|FAILED\|PANIC\|ACTION\|FOLLOWUP\|SECURITY\|SECRET\|TOKEN\|PASSWORD\|KEY` |
| [Config files](/docs/proxy/compressors/config) | `ERROR\|FAIL\|FAILED\|FATAL\|PANIC\|EXCEPTION\|WARNING\|SECURITY\|SECRET\|TOKEN\|PASSWORD\|DENIED\|REJECTED\|ROLLBACK` |
| [Tables](/docs/proxy/compressors/tables) | `ERROR\|FAIL\|FAILED\|FATAL\|PANIC\|EXCEPTION\|WARNING\|SECURITY\|DENIED\|REJECTED` |
| [Text](/docs/proxy/compressors/text-and-html) | `ERROR\|WARNING\|IMPORTANT\|NOTE\|ACTION\|FOLLOWUP\|SECURITY\|SUMMARY\|CONCLUSION\|DECISION\|RECOMMENDATION` |

The log and terminal patterns also match line shapes rather than words: an indented `at ` or `File "` stack
frame, a `.go:NNN` location, a leading `--->`, and `caused by`. Terminal adds a `file:line:col:` compiler
location, any `…Error` or `…Exception` type name, and `exit status` with a non-zero code.

**A marker states facts about what it replaced.** A count alone says nothing about whether the elided rows
mattered, so a marker carries four kinds of fact computed from those exact units at the moment they are
replaced: a constant, an enumeration with exact counts, a numeric range, and identifier coverage. A field
whose name suggests a credential is dropped from the marker, since a marker gets quoted and pasted far more
freely than the body it replaced. Each compressor page prints the forms and conditions for its own markers.

**A marker never costs more than it saves.** The whole summary is capped at 160 bytes and at a quarter of
the bytes it replaced, with a floor of 96 bytes so a small anomalous class still gets room for a fact or
two. Runs shorter than three units are not collapsed on the strength of a count, and a single elided unit
has no class to describe, so it gets no summary.

**Compressors do nothing else.** They never count tokens, never write to the recovery store and never touch
the network. The engine does all of that around them, which is why adding one is a file plus its tests.
