`caveman claude` launches Claude Code with its provider base URL pointed at a local proxy, starting that
proxy first if nothing is listening. The same shortcut exists for every agent profile the CLI ships, and
`caveman disable` puts each one back.

Wiring your own application instead of a coding agent? [The proxy](/docs/proxy) has the base URL swap.

```bash
caveman claude
```

```bash
caveman wrap claude
```

The first form installs the integration for that host once and leaves it installed, so plain `claude` stays
routed in later sessions. The second runs one session through an ephemeral environment and writes nothing to
your config files.

```bash
caveman help wrap
```

```text
usage: caveman wrap [--off|--pixel] [--workflow <slug>] <agent> [args...]
  (default)    ephemeral stack: S4 compression + TOON best-of + recovery/output shrink where host supports a temp pack
  --off        byte-safe pass-through metering only — nothing is rewritten
  --pixel      lossy text→PNG pixel mode (model-gated); originals recoverable via caveman_retrieve
  --workflow   label this session's traffic (x-cave-workflow) so it groups by name in the dashboard
```

S4 is the engine's lossy but recoverable class, the one that may only run once the original bytes are stored;
[The engine](/docs/proxy/engine#the-pipeline) has the ladder it sits at the top of.

Both doors run the proxy in `compress` mode, which is the default of the `think.mode` setting they resolve.
A bare `caveman start` is the exception: with no agent to bind recovery to, it resolves to `record` and
rewrites nothing.

## Recovery has to be installed

The proxy elides bytes from a streaming turn only when the agent can ask for them back, through the
`caveman_retrieve` tool of the [MCP server](/docs/mcp). Each door registers it differently:

| Agent | `caveman <agent>` | `caveman wrap <agent>` |
|---|---|---|
| Claude Code, Codex | The install writes the server into the agent's own config | A temporary copy of the same server, for that session only |
| Gemini CLI, Hermes, opencode | The install writes the server into the agent's own config | After `caveman mcp install <agent>` has run once |
| Pi | The bundled Pi extension carries it | The bundled Pi extension carries it |
| OpenClaw, Kilo Code, Qwen Code | Falls through to the wrap door | OpenClaw from its routed config; Kilo and Qwen after `caveman mcp install <agent>` |
| Aider | Nothing | Nothing. `caveman mcp install aider` prints a registration to make by hand rather than writing one |

```bash
caveman mcp install gemini
```

Kilo Code and Qwen Code are the two the proxy is never told about out of band. Both can apply policy after
the config caveman wrote, so the proxy reads the retrieve tool out of each request instead of trusting a
marker. Without a reachable tool the wrap still starts, non-streaming API-key traffic still compresses, and
the run banner says what is off:

```text
MCP recovery missing — streaming turns and Claude Pro/Max sessions pass through uncompressed (non-streaming API-key traffic still compresses)
```

That line comes from the CLI's own off-state table, under the `caveman · <mode> · <agent>` banner the wrap
prints as it starts.

## Verify

In another terminal, while the wrapped agent is running:

```bash
~/.caveman/bin/caveman-proxy status
```

```json
{
  "owner": "wrap",
  "mode": "compress",
  "recovery_via_mcp": true
}
```

Trimmed from one real run: the full document also carries the port, the pid, the instance token, the start
time and the binary version. `owner` is `wrap` for a proxy a wrap started and `start` for one `caveman start`
launched, `mode` is what it does to payloads, and `recovery_via_mcp` is whether the agent's retrieve tool was
proven before the session began.

## The agents

One JSON profile per agent in `agents/profiles/` in the product repository decides how each host is pointed
at the proxy.

| Agent | Vendor | How it is pointed at the proxy | `caveman <agent>` |
|---|---|---|---|
| Claude Code | Anthropic | `ANTHROPIC_BASE_URL` | installs the integration |
| OpenAI Codex CLI | OpenAI | environment for an API key, an ephemeral `CODEX_HOME` for a ChatGPT login | installs the integration |
| Gemini CLI | Google | `GOOGLE_GEMINI_BASE_URL`, `GOOGLE_VERTEX_BASE_URL` | installs the integration |
| Hermes Agent | Nous Research | `CUSTOM_BASE_URL`, `CUSTOM_API_KEY` | installs the integration |
| opencode | sst | inline config through `OPENCODE_CONFIG_CONTENT` | installs the integration |
| Pi | pi.dev | bundled extension loaded with `--extension` | installs the integration |
| Aider | OpenAI / Anthropic | `OPENAI_API_BASE` | one session through `wrap` |
| Kilo Code | Kilo Code | inline config through `KILO_CONFIG_CONTENT` | one session through `wrap` |
| OpenClaw | OpenClaw | merged config through `OPENCLAW_CONFIG_PATH` | one session through `wrap` |
| Qwen Code | QwenLM | settings overlay through `QWEN_CODE_SYSTEM_SETTINGS_PATH` | one session through `wrap` |

Agents in the last four rows have no `caveman <agent>` install, so `caveman kilo` falls through to the same
ephemeral path `caveman wrap kilo` takes. Kilo reads `kilo.json` or `opencode.json` in its config directory,
and either one in its `.jsonc` form; wrap passes it a routed config through `KILO_CONFIG_CONTENT` instead.
OpenClaw and Qwen Code get a merged copy: wrap reads `~/.openclaw/openclaw.json` or
`~/.qwen/system-settings.json`, merges the routing overlay into what it found, writes the result to a
temporary file with mode `0600`, and deletes that file when the session ends.

## What `caveman claude` does, in order

<Steps>
<div>
Passes `--help` and `-h` straight to the host binary and stops there, so asking another program for its usage
never installs anything.
</div>

<div>
Installs the integration for that host if no journal exists for it, which is the same set of user-scoped
writes `caveman enable claude` makes. An existing journal means routing is already owned and this step is
skipped.
</div>

<div>
Resolves the host binary on `PATH`. A missing binary prints the install line for that agent and exits 127.
</div>

<div>
Starts `caveman-proxy` detached when the target is loopback and nothing answers on that port, then waits up
to two seconds for the port to accept connections.
</div>

<div>
Launches the host binary with your arguments on the same terminal, forwards `SIGTERM` and `SIGHUP` to it, and
exits with the child's exit code.
</div>
</Steps>

Two things send `caveman <agent>` down the `caveman wrap` path instead: a first argument that starts with
`--`, and a `.caveman/agent.lock.json` in the current directory. The lock is checked on the wrap door, so a
locked project keeps routing through it.

## Aider and Codex

Aider has no persistent integration, so `caveman aider` runs the ephemeral path. `caveman enable aider` is
still accepted and installs a read-only coding-policy file; the recovery tool and command-output rewrite that
the other hosts get are unavailable there.

Codex is wrapped like the rest but skips the command-output shrink hook, because its runtime rejects that
rewrite ([openai/codex#18491](https://github.com/openai/codex/issues/18491)). Compression of provider
requests is unaffected. Codex also gates hook approval behind its own `/hooks` command, so approve the
Caveman hooks there when it asks.

## Enable and disable on their own

```bash
caveman enable claude
```

`enable` prints the writes it plans before it makes them: the file for each one, the routing value it sets,
the recovery binary it points at, and the lifecycle hook command. It takes `claude`, `codex`, `hermes`,
`gemini`, `opencode`, `pi` and `aider`, or `--detected` for every one of those found on `PATH`. Each
installation is journaled, with the previous contents of every file it touched.

## Undo

```bash
caveman disable claude
```

```text
usage: caveman disable <claude|codex|hermes|gemini|opencode|pi|aider> | disable --all
```

`disable` replays the journal backwards and restores what was there before. `--all` does it for every
integration that has a journal. Sessions started with `caveman wrap` need no undo: the environment they ran
in is gone when the process exits.
